# Structural CSV cursor — unfinished prototype

This isolated prototype is **unfinished and unvalidated**, is not integrated with any selected entry, and has no performance result. `cursor.rs` SHA-256 `3f76a6485104f31e9780955cb5c63204285ac28fc2e6ec2ee405c428ce6504a6` should be verified before use (see `shasum -a 256 cursor.rs`). Only a native ARM library compilation was run; no tests, independent review, target execution, protected-page test or benchmark has been performed. The x86 AVX2 path has not been compiled or exercised here.

The concept classifies quotes, commas, CR and LF in 32-byte blocks, carries quote parity between blocks, and emits outside-quote structural offsets and quote-byte counts using a scalar fallback and runtime-gated x86 AVX2. It was started as a potential replacement for separate per-field delimiter scans; scanning numeric bytes and computing prefix parity may cost more than the current approach. It is not evidence of speedup.

Before any integration, the parent specified that the cursor must emit **only** outside commas and LF, leaving CR in the amount span, and expose field start/end in addition to quote count. This source still emits CR and exposes positions only; it does not satisfy that interface. Exhaustively validate scalar versus AVX2 across 31/32 quote-pair splits, byte tails and protected pages, compare randomized data and quote-count semantics to an independent oracle, test hostile multiline CSV and unbounded records, review integer shifts/bounds and repeated EOF calls, then check actual Linux x86 AVX2 and full reference output. Runtime progress and performance are unknown.
