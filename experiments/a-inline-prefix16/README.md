# A inline 16-byte endpoint prefixes (not selected)

The experimental candidate stores each endpoint's exact first 16 bytes, full hash, start, length and ID inline in each open-addressing slot. Full endpoint equality remains mandatory: slots first check the masked prefix and length, then compare the rest for lengths above 16. Stable IDs and growth reinsertion follow the selected table. This differs from the earlier inline-slot experiment, which retained the endpoint bytes only by reference. Exact current compact-record baseline SHA-256 is `4af40353f517f566217b0f882ec25d8002f61d211dcc479c53f8a1dd5de7ed88`. The Linux source retains its original mapping flags; only temporary native Mac builds changed MAP_ANON 0x20 to 0x1000.

Eleven randomized warmed full-seed native shared-ARM pairs gave candidate/baseline median wall 0.063541/0.058957 s and CPU 0.204187/0.205935 s. A 15-pair repeat gave wall 0.055258/0.049406 s and CPU 0.203629/0.204443 s. All 60 full output hashes including warmups matched. Host contention and processor architecture limit interpretation; these are not official x86 or cgroup measurements. No stable wall gain was found, so candidate remains unselected. Forced collisions, alternate-input correctness and independent safety review were not run. `report.json` and `repeat.json` retain native samples. No Mac Docker was used.
