# Rust B worker-count screen (not selected)

`test-override.rs` is the selected short-token AVX2 implementation at commit `e88ee2c` with one test-only change: the worker count is read from `SD_TEST_THREADS` when present. Without that environment variable, its default remains `available_parallelism()`. Its source SHA-256 is `67c589286893f3f1bcb7a8a3ffc05c055ebaa63dceedc6ef6198b7df4cfdb4ba`; the unchanged selected source SHA-256 is `d0f0d79f3f646275d2e33ef34659eba5bca56fb2bb16504025f10a800e88cc49`. The override exists only to screen worker counts; it is not submitted.

Five randomized measured full-data runs per count after one warmup each all matched the published full-seed SHA-256. On the shared native ARM Mac, the medians were 0.429264 / 0.303622 / 0.278258 / 0.273602 / 0.273313 / 0.305399 seconds for 3 / 6 / 8 / 9 / 12 / 16 workers respectively. Median CPU seconds were 1.210835 / 1.517362 / 1.636457 / 1.657897 / 1.688865 / 1.750074; maximum native process RSS ranged from 531.8 to 542.2 MB. The host reported eight CPUs to Python, and other jobs may have been active. Native process RSS is not cgroup memory and the ARM scalar tokenizer is not the scoring box's AVX2 path. The difference between 8, 9 and 12 is too small to choose a production count from this screen. `mac-arm-report.json` retains every run.

The distributed top-ten/duplicate/overlap reference fixture passed each of the six worker counts. For a target x86 screen, compile `test-override.rs` with the same release flags and x86-64-v3 as the selected candidate, then run `python3 experiments/b-rust-worker-sweep/compare.py --binary /path/to/solution --data /path/to/full-b --report /tmp/b-workers.json`. It verifies every published output hash and records native wall/CPU/RSS; run without other load and measure official cgroup memory separately. No Docker was used.
