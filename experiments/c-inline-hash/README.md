# C sharded inline name/group table (not selected)

`baseline.rs` is the exact selected CRLF implementation (SHA-256 `3e181c76981348a96b48470844ee0f8988847d32164ff935a211024861c86ad4`). The candidate replaces the std HashMap/bit-vector pair in each shard with a growing linear-probe table containing a borrowed exact name, precomputed hash and four inline group-bit words, avoiding a second name hash and bitmap indirection. For more than 256 groups it falls back to the original dictionary logic. Output depends on the supplied input. It remains an unreviewed prototype: forced hash collisions can make probing quadratic, and no alternate-seed, overflow or independent correctness review has been done. Do not promote on this evidence.

Two randomized full-seed shared ARM screens after warmup matched all 56 public hashes. First 11-pair candidate/baseline median wall 0.14006/0.15308 s, CPU 0.80357/0.85698; repeat 15-pair median wall 0.13381/0.12725, CPU 0.78055/0.78674. Maximum native process RSS ~231 MB versus ~226 MB. Samples are in the JSON reports. The repeated reversal and flat CPU show no stable speed win; these are not x86 or official cgroup measurements. No Mac Docker was used.
