# Track B worker-count experiment

These isolated variants derive from exact restored B SHA-256 `322cc95ee08cf6d4abc5e1b52240753f66c7eaf89ab669cb6d72b0a8487dc458`. `cap6.rs` SHA-256 `3c591a778edb7907445b0482fbd7c69a4ed2c71afd9e94f5c66c9ec624b33d3e` and `cap12.rs` SHA-256 `276e28627c49b1b73e8a924b31fc2e18c5b03eb4463d43e014e7ea7773f54bb7` differ only by capping the available CPU count at six or twelve. Each naturally uses fewer if the process has fewer available CPUs. `test-override.rs` adds an `SD_TEST_THREADS` environment override solely for screening; without it behavior equals the selected default. No candidate is selected by this experiment.

On the shared native ARM host reporting eight logical CPUs, 15 randomized warmed pairs gave median 6-worker wall 0.356803 s, CPU 1.541666 s, max process RSS 534,528,000 B; 12-worker wall 0.310164 s, CPU 1.655437 s, max RSS 544,735,232 B. A separate five-run-per-count sweep gave wall medians 0.654113/0.382547/0.318741/0.389845/0.295908/0.307336 s for 3/6/8/9/12/16. Shared load and distinct core/SMT topology make these noisy ARM results **not** predictive of the official i5-13500 six P-core/12-thread machine or cgroup memory. Both JSONs retain exact samples. All 68 sweep outputs and each exact cap source full run matched the published hash; warmups are included.

Each forced override of 6 and 12 passed 40 reference corpora, distributed top-ten/overlap, >1 MiB document boundaries and 250,000-document/19,000-duplicate-phrase stress. Independently compiled exact `cap6.rs` and `cap12.rs` passed full hash, 40 reference corpora, long boundaries and duplicate stress; the latter used only the host available CPU count if it was below 12. These tests execute native ARM scalar tokenizer, not actual Linux x86 AVX2. No Mac Docker was used.

For a serialized native x86 VM sweep, compile `test-override.rs` with matching offline release flags and `-C target-cpu=x86-64-v3`, then run the included generic `experiments/b-rust-worker-sweep/compare.py` with `--counts 6 12 --runs 15`, separately generated seed-1 data, and no concurrent work. Run reference/edge and AVX2 guarded-page checks for both counts. The dot VM and official i5 have different scheduling and SMT; use controlled official practice to resolve the latter, and measure peak cgroup memory separately.
