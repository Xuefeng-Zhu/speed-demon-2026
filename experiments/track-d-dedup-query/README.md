# In-run duplicate-query grouping (experimental, not selected)

This prototype groups identical `(s,t)` inputs during the timed run, computes each distinct query once from the runtime graph, and writes the result separately in every original input position. No results are shipped with the image or persisted between runs. The published spec says duplicate lines receive identical output on their own lines and preprocessing is allowed and timed; this prototype has not received an organizer clarification. Baseline is the positioned-read D source present at this experiment's creation.

The candidate passed all full seed-1 hashes, 16,000 random queries, 36,864 exhaustive three-node queries, 376 directed chain/cycle fixtures, a maximum-size maximum-weight chain and 6,000 repeated/unreachable queries. Nine shared ARM native pairs (`report.json`) gave median 0.33375 vs 0.38433 s baseline, CPU 1.85454 vs 1.91893 s; the 11-pair repeat (`repeat.json`) reversed to 0.29341 vs 0.28962 s, CPU 1.83324 vs 1.82525 s, max native RSS 534,953,984 vs 535,265,280 B. Host contention and differing ordering make the result inconclusive. This is not official x86/cgroup evidence; candidate remains unselected. No Mac Docker was used.
