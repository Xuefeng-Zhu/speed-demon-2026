# D narrow u16 epoch tags (unselected)

This isolated candidate changes only the narrow `Search32` state of the selected hybrid. Baseline SHA-256 `671c639be3400209e83e080dfb54947affd30ca71dc34ec17804d24d70292d9c`; candidate SHA-256 `7cc957020eb50b14ce7c77ad293b20e1ebdbce0b86660db9f127e735dd752289`.

A per-vertex `u16` epoch tags a pair of complemented u32 distances. On first visit in a query, the epoch is updated and both stale slots are zeroed; the fixed-capacity FastHeap and exact wide fallback remain unchanged. Per-query touched-vector clearing is eliminated. Epoch zero is unused; on wrap, all epoch tags are cleared before epoch 1 is reused. Self-queries and cap-zero do not mutate this state. Each successful relaxation reads the opposite side only after the node has been stamped for the active query. Stale popped entries originate only from the active query, and heap cleanup remains unconditional after every nontrivial narrow search, including pool exhaustion.

`python3 experiments/track-d-u16-epoch-hybrid/verify.py --extremes` passed debug/overflow checked capacities 0, 1, 2 and 65,536; its internal test ran 131,080 alternating queries per capacity, crossing two u16 wraps when capacity was nonzero, with side-state, self, unreachable, cutoff and forced-fallback cases. Every answer matched the known exact result and both queues were empty after each query. It also passed the independent 16,000 random graph queries and 36,864 exhaustive graph answers for each capacity, cutoff−1/cutoff/cutoff+1, packed 2^21/2^21+1 node and weight boundaries, full-size maximum-weight chain, and 6,000 repeated/unreachable queries. A separate static review found no concrete defect. These are finite ARM tests, not an all-input proof; x86, official scoring and parent-cgroup memory are unverified.

Compared with the selected narrow state, `seen` requests 2 bytes per node and replaces a touched-vector request of 4 bytes per node. RSS depends on which pages are actually touched and allocator/cgroup behavior. The same fixed queue cap, wide fallback, and known absence of a formal whole-cgroup 8 GiB bound remain. This source is not selected.

On the verified full public seed-1 dataset, one warmup pair and 15 randomized native ARM pairs all produced the published output hash. Median candidate/baseline wall was 0.295427/0.265247 s (candidate 11.4% slower); CPU was 2.003625/1.816285 s. Maximum native process RSS was 612,712,448/612,433,920 bytes. Raw observations and flags are in `arm-a.json`; these are shared Mac measurements, not target x86 or cgroup scores. Given the clear wall and CPU regression, the candidate remains unselected and no repeat or target test is recommended.
