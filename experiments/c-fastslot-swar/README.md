# C fast-slot + SWAR scanners (not selected)

This prototype combines the isolated atomic name-cache candidate `experiments/c-fastslot/candidate.rs` with `c-swar-field`'s guarded byte finder and `c-swar-integer`'s guarded positive id/region parsing. The two parser functions are byte-for-byte identical to their individually tested forms; generic numeric fallback is retained. The baseline in this folder is the exact fast-slot candidate, not the selected implementation. Both candidates compute all data-dependent results. The combined candidate is not selected.

Against fastslot alone, 9 and 15 randomized full-seed native ARM pairs measured 0.09273/0.11240 s and 0.09052/0.11041 s candidate/baseline median wall; CPU 0.53236/0.68153 and 0.53392/0.67980 s. Direct 15-pair comparison versus the selected baseline was very heavily contended: candidate/baseline medians 0.15946/0.41664 s wall and 0.68477/1.06606 s CPU. Full samples are preserved in JSON. All 84 executions including warmups matched the published hash. These are shared ARM timings, not x86 or official; the parent reported the fastslot approach alone regressed on dot VM without a precise magnitude, so do not infer a target win.

The combined source passed 24 mixed reference corpora at each of five worker counts, eight 310-group normal and forced-hash reference comparisons, and the atomic fastslot collision/race check. The identical SWAR helpers separately passed 15,145,280 delimiter comparisons, 76,924 macOS guard-page checks, 19,547 field comparisons, 10,001,599 integer comparisons and 36 integer guard-page checks; these results are documented with code in sibling `c-swar-field` and `c-swar-integer` directories. No Linux x86 checks or measurements were performed and no Mac Docker was used.
