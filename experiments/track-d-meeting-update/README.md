# D meeting check on successful relaxation (experimental)

Relative to Track D at commit `1b2da3d095acd09779f08205f9329f79b7ba40d7`, this candidate tests the opposite-side tentative distance only when an edge improves its side's distance. Each successful improvement checks for a meeting; if a later non-improving edge reaches a node already reached from both directions, the existing pair of tentative distances was already considered when the later of those two distances was last improved. This invariant needs independent review before adoption.

On shared macOS ARM, eight randomized-order full seed-1 pairs following two warmup pairs all matched the published SHA-256. Median wall was 0.787742 s candidate versus 0.832253 s baseline; median CPU was 2.865190 versus 3.123072 s; peak per-process RSS was 562,167,808 versus 559,087,616 bytes. `mac-arm-bench.json` records every run, including warmups. These are noisy native results, not an official cgroup score or an x86 measurement.

Both candidate and baseline were built with `rustc --edition 2021 -O -C lto=fat -C codegen-units=1 -C panic=abort`. The candidate passed 80 seeded random directed graphs and 16,000 independent Dijkstra-oracle queries in each of six builds (default worker count and test-only forced counts 1, 2, 3, 7 and 32), including zero and maximum u32 weights, duplicate edges and disconnected nodes. Repeat with `python3 experiments/track-d-meeting-update/oracle.py /path/to/candidate`; compare to a release-compiled selected source. More boundary testing, independent review, source-count and x86/cgroup measurements are needed before promotion. Source SHA-256: `2c4bcd2771cf79eceb37ee309edaeda4675db6f026458f483871f784a268755e`.
