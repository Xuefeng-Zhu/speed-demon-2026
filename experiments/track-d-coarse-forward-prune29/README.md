# Forward-only pruning on coarse queues (unselected)

Exact current coarse baseline SHA-256 `2a2a325a1c87e4bc68c260e0d80353e0b8f1f9a7b5be81b1ffeaaede6d813f9d`; candidate `c33d3984871fb22ed7c2d678b3a3562ac82d46cb952a8a0461980301c5a553ef`. The candidate keeps backward search unpruned. After a finite best path exists, a forward relaxation with `nd + b >= best` (where `b` is the backward minimum quotient bucket start) first considers any known exact-path reverse label at that destination, then skips insertion. Narrow cutoff tracking, fixed pool and exact wide fallback are unchanged. No target claim, proof of all inputs, cgroup bound or official score is established.

Reasoning to independently verify: as every strict reverse decrease is enqueued and buckets below `b` are fully drained, all true reverse distances strictly below `b` are final; stale entries can lower but cannot raise the bound. If the true reverse distance at the destination is at least `b`, a skipped path cannot beat the current best; otherwise the known final reverse label is explicitly considered before the skip. Backward processing remains unpruned. Zero weights, repeated decreases, empty-frontier termination, cutoff and fallback need particular care. `nd` and `b` are below u32 max and their sum fits u64.

Testing, independent review and native measurements pending. No Mac Docker.
