# First/last endpoint hash with bounded fallback (unselected)

`baseline.rs` is exact selected A SHA-256 `4af40353f517f566217b0f882ec25d8002f61d211dcc479c53f8a1dd5de7ed88`; `candidate.rs` is SHA-256 `e810dd3382a80ee8258afd6a6f18d807916d1bff7a96dd6341ed26f528c69672`. The candidate scans endpoint delimiters without per-word hash operations, hashes endpoint length and first/last bytes, and uses the existing exact comparison with a 48-occupied-probe bound. On a bound violation it discards and reparses the whole shard using the original table, and successful shards rebuild canonical hashes in ID order. It derives everything at runtime. This structured hash can deliberately collide on names sharing prefixes/suffixes; exact comparison and fallback are essential, and independent adversarial/collision validation is not done.

A native Mac ARM 12-worker screen changed only the anonymous mmap flag in temporary build copies. After warmup, 11 randomized full seed-1 pairs all matched the official output SHA-256. Candidate/baseline median wall was 0.050383/0.047235 s and CPU 0.237717/0.200131 s: respectively 6.7% and 18.8% slower. `arm-report.json` preserves individual data and hashes of Darwin-adapted builds. A separately instrumented full-seed candidate reported zero shard fallbacks, so the observed CPU increase was not due to restarting any shard in that run. The shared Mac and short sample do not establish x86 or official performance; no full adverse reference, correctness review, repeat or target run was performed. The candidate remains isolated and is not recommended for VM testing given the size of the regression. No Mac Docker was run.

The script `compare.py --data /path/to/full-a --report /tmp/a-firstlast-report.json --runs 11 --threads 12` compiles the original Linux files on supported Linux; on macOS use temporary copies with the anonymous mmap value changed from 0x20 to 0x1000, preserving source hashes separately. Native process RSS is not an official parent-cgroup peak.
