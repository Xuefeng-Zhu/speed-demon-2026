# Track A 16-byte endpoint equality (experimental)

The candidate replaces pairs of eight-byte equality comparisons with unaligned 16-byte comparisons only when at least 16 bytes remain in both equal-length endpoints, followed by the existing 8-byte and masked-tail handling. The hash, table probing, parsing and output are unchanged. Reads stay inside the endpoints for the 16-byte path; the inherited tail path uses the padded mapping. This is not selected and needs independent source review and x86 AVX-capable testing before use.

On shared macOS ARM, using temporary binaries with only Linux `MAP_ANONYMOUS` 0x20 changed to Darwin 0x1000, all seed-1 hashes passed. Nine randomized measured pairs gave median wall 0.063965 s candidate versus 0.066497 s baseline (CPU 0.203337 versus 0.207297 s); a 15-pair repeat gave 0.040587 versus 0.042629 s (CPU 0.191434 versus 0.192981 s). The host was shared; individual times and native process RSS are in `mac-arm-initial.json` and `mac-arm-repeat.json`. These are not x86 or official results and the observed gain is small.

An overflow-checked exact equality property exercised lengths 0–125, all 8×8 relative alignments and every byte mismatch. Normal and forced-all-hashes-equal builds passed the 2,422-endpoint reference/growth fixture across workers 1/2/3/7/12/32. The candidate passed synthetic 0/1k/100k/100k cases, 14 page-end reference fixtures and the 132,624-group latency grid. No Mac Docker was used.

For target testing compile `candidate.rs` and `track-a/src/main.rs` with identical pinned release flags and x86-64-v3, run `python3 experiments/a-equality16/property.py`, and use `python3 experiments/a-rust-percentiles/compare.py --baseline /path/to/baseline --candidate /path/to/candidate --data /path/to/full-a --report /tmp/a-equality.json --runs 15 --threads 12`. Re-run the synthetic, page and `a-dualhash/stress-growth.py` tests with a forced-collision build. Inputs must be generated separately; native RSS is not cgroup memory.

A subsequent 15-pair six-worker screen reversed the ordering: candidate median 0.061543 s versus baseline 0.055228 s, CPU 0.186371 versus 0.185543 s. All full hashes matched; the shared-host result is in `mac-arm-six.json`. Given the reversal and marginal CPU differences, no speedup is established and the current implementation remains selected pending controlled target measurement.
