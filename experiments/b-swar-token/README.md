# B eight-byte token scan (not selected)

This isolated variant changes only the token-length scan: it classifies eight bytes per word with high-bit-protected per-byte subtractions, falling back to the existing byte table for fewer than eight remaining bytes. Bytes outside ASCII are rejected. It preserves the exact plan dictionary, bounded phrase summaries and bitmap cap. The baseline source is the selected Rust B at 4f2d688. `property.rs` exhaustively places every byte 0–255 at 32 positions and 16 starting offsets, comparing against the scalar tokenizer: 131,072 cases passed with overflow checks. The candidate also passed 40 mixed-reference corpora, distributed top-ten/duplicate/overlap, and >1 MiB boundary fixtures.

All sixteen full seed-1 outputs, including one warmup per binary, matched the published SHA-256. Seven randomized measured paired native shared-Mac ARM runs gave median wall 0.448165 s candidate versus 0.420220 s baseline and median CPU 2.4450 versus 2.2859 s. Other agents were active; native process timing is not the official x86/cgroup score. The candidate was slower in this screen and is not selected; see `bench.json`.

To reproduce the property check: `rustc --edition=2021 -C opt-level=2 -C overflow-checks=yes experiments/b-swar-token/property.rs -o /tmp/b-swar-property && /tmp/b-swar-property`. To compare full data, compile the two Rust sources with identical release flags and run `python3 experiments/b-rust-lengthhash/compare.py --baseline /path/to/baseline --candidate /path/to/candidate --data /path/to/full-b --runs 7 --report /tmp/b-swar.json`.
