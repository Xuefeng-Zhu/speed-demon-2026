# Dynamic owner cache-capacity screen — unselected

`baseline.rs` is the exact selected four-times dynamic-partition source SHA-256 `bcd4d7715bffd8a3dc062cad6e7aa0886a96d659fcc9170735c4d4d123f67eae`. Each candidate changes only `CACHE_SLOTS`: 4,096 (`7afedcfad24447fa36828c89cd476bd777838b50bc68f75a57e839c3430ab3ce`), 8,192 (`c7f5b409b25f7a1502ccb11e82fba6eeceffb60f7c67d3bd9e9f982dd416d5a6`), 16,384 (`a452f954e3e75dd9c4e7968564fc18f433014c77331c0cce2618c67e5ff63b45`), or 65,536 (`b0038fb4a40941ea4c0bf299e5849e5b83097d8cbb28248ee5868b2907c314d2`). Full-hash and exact-byte checks, promotion and fallbacks are unchanged. Prior `c-rowcache-capacity` screens used the older single-owner-per-worker architecture, so this is a separate rebase.

On generated full public seed 1, serialized native shared-macOS ARM screens of 11 randomized pairs after one warmup had baseline/candidate median wall seconds: 4,096 `0.068698/0.069049`, 8,192 `0.068208/0.066958`, 16,384 `0.069278/0.067263`, and 65,536 `0.069677/0.072626`. A 15-pair repeat gave 8,192 `0.070191/0.069378` and 16,384 `0.075444/0.073709`. All 160 measured and warmup outputs matched the published full hash. 8,192 CPU medians in the repeat were `0.423075/0.425909` seconds and 16,384 `0.423570/0.427970`; process RSS medians were approximately 282.4/277.8 and 282.0/279.4 MiB respectively. Raw samples and native-unit details are in the JSON files. Wall differences were small and CPU slightly higher in repeats; this is not x86, official performance or parent-cgroup memory evidence. No stable substantial benefit is established; no candidate is selected.

`verify.py --capacity N` is prepared to test mixed references, forced equal hashes and the existing exact cache replacement/collision-promotion model. It has **not** been run on any variant. No alternate-input, independent review, actual x86, official cgroup or >4 GiB full parsing validation has been performed. The ARM screens support retaining the current baseline and do not justify target testing alone. No Docker was run on the Mac.
