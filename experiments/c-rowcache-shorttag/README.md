# C compact row-cache tag — preliminary, unselected

`baseline.rs` is exact selected 32,768-slot row-cache SHA-256 `76b341e2b7e880fe4ceeee220206a63b48cd247bba4448aa7991a7ad825e8dd2`. The variants replace the 16-byte `(u64 full hash, usize row)` cache entry with an 8-byte `(u32 high hash tag, u32 row)` and vary capacity. Hits still compare the exact immutable name bytes. Rows not representable below `u32::MAX` are never cached; `u32::MAX` is the empty sentinel. Equal names must yield identical full hashes through all parser paths: this is an inherited invariant of the selected parser and is necessary for the lookup. Distinct hashes with the same truncated tag/index are harmless only because exact name bytes are checked. This proof has not been independently reviewed and non-public inputs, collision/sentinel stress and >4 GiB processing have not been checked for this experiment. No candidate is target-ready.

Nine paired warm-cache full seed-1 native ARM samples per variant plus one warmup pair all matched the public hash (60 executions). Candidate/baseline median wall seconds were 0.07164/0.07130 (32,768 slots), 0.07238/0.07273 (65,536), and 0.07723/0.07619 (131,072). Median CPU seconds were 0.4233/0.4307, 0.4301/0.4145, and 0.4223/0.4301 respectively; approximate candidate/baseline native RSS in MiB was 271.9/274.3, 274.0/274.6, and 277.8/273.2. Raw results are in `screen-*.json`. These shared ARM results do not show a reliable or substantial speed win, and are not official, Linux/x86 or cgroup measurements. Selected code is unchanged.
