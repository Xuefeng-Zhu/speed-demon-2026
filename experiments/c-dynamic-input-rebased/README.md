# C dynamic input scheduling on current dynamic owners (unselected)

`baseline.rs` is the selected dynamic owner source SHA-256 `bcd4d7715bffd8a3dc062cad6e7aa0886a96d659fcc9170735c4d4d123f67eae`. `candidate.rs` SHA-256 `480f1a964ab436cbd67b6abfad8c65a8e9d01c26b89e9b323db03239eb7de34f` changes the packed parser to schedule up to four times as many CRLF-aligned input chunks via an atomic counter, while preserving the same worker-local aggregators and owner bins. The unrepresentable-input fallback remains unchanged. The chunk cuts are precomputed once, monotone, and if the next desired cut falls within an oversized record whose end is already known, the previous boundary is reused. Every chunk shares endpoints with its neighbors. This avoids the repeated rescan of the same long record identified in `experiments/c-dynamic-input/README.md`, but this new variant has not received independent verification of cut/long-record/worker behavior.

In two 15-pair randomized native ARM full-public-seed screens after one warmup, candidate/baseline median wall seconds were `0.074203/0.074471` and `0.072247/0.070812`; CPU seconds were `0.425235/0.419833` and `0.427520/0.420872`. All 64 output hashes matched the public full expected hash. Data and individual observations are recorded in `arm-a.json` and `arm-b.json`. Results are tied then slower, with higher CPU in both batches, so this candidate remains unselected. Shared ARM timing is not Linux x86, scoring-box or cgroup evidence.

No alternate reference, forced-collision, long-record, independent concurrency review, Linux x86 or cgroup checks were performed on this exact candidate because no performance win was shown. No Mac Docker was used. To reproduce, compile `baseline.rs` and `candidate.rs` using matching `rustc --edition=2021 -O -C lto=fat -C codegen-units=1 -C panic=abort` flags, then run `python3 experiments/c-dynamic-input-rebased/compare.py --baseline <base> --variant <candidate> --data <independently-generated-full-seed-1> --runs 15 --report <report>` without competing native benchmarks. The comparator checks output hashes and process RSS, not cgroup memory.
