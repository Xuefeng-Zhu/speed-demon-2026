# Narrow-hybrid neighbor distance prefetch (unselected)

The baseline is the exact selected batch16 D source SHA-256 `7fd333be25133a78264cb4b84441de46d4c8bcbfd73914af23761f23d8c47f17`. `generate.py` produces `ahead1`, `ahead2`, and `whole`, which prefetch a later neighbor's per-worker narrow distance slot while otherwise retaining the exact relaxation loop, fixed pool, u32 cutoff and indexed wide fallback. The helper emits ARM `prfm pldl1keep` or x86 `_mm_prefetch` T0. It uses a wrapping pointer derived from the live owned distance allocation; only valid input vertex IDs are permitted. `control` adds unused helper methods while retaining the original loop. It is **not** a same-instruction-cost control for extra lookahead work: the compiler can eliminate all unused code. No selected file changes.

An independent static review found no concrete row-bound, node decoding, pointer-provenance, search-order or fallback defect for valid 64-bit graph input, but this is not an all-input proof. `verify.py` on ahead1 built forced pool capacities 0, 1, 2, 15, 16, 17 and 65,536 with debug/overflow checks; each passed 16,000 random and 36,864 exhaustive graph answers plus cutoff tests, packed/wide node boundaries and max-weight/repeated-query extremes. All four control/ahead1/ahead2/whole builds separately passed the random and exhaustive suites, and ahead2/whole passed packed/wide node-boundary checks. These are ARM tests; Linux x86 intrinsic execution, guarded-page row endings, cgroup memory and hidden data remain unverified.

One randomized 9-round five-way ARM screen (`arm-screen.json`) was contaminated by overlapping correctness work; do not use its wall medians. A separate 11-round randomized clean screen (`arm-repeat.json`) compared baseline, ahead1, ahead2 and whole after warmup. All 48 outputs matched the official full seed-1 hash. Median wall seconds were 0.247676, 0.255364, 0.252468 and 0.256293 respectively; median CPU seconds 1.784600, 1.850903, 1.832590 and 1.845329. All three hints were slower by about 1.9–3.5% wall and 2.7–3.7% CPU in this one native ARM run. This is not x86, official scoring or parent-cgroup evidence; the experiments are not selected and no target speedup is established. No Docker was run on Mac.

Input data and outputs are not included.
