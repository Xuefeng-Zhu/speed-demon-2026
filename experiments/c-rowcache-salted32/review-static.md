# Independent static review of low-32 event fingerprint

Reviewed candidate SHA-256 `5447d5c7d77e616b60c843c20f58cacc6bd152e6c9337e1a417f7b1768d863aa` against selected row-cache baseline SHA-256 `76b341e2b7e880fe4ceeee220206a63b48cd247bba4448aa7991a7ad825e8dd2`. The review found no new correctness defect in the source diff. This is a static review, not a proof of all implementation behavior.

- The producer computes the existing full u64 name hash and uses that full value for bucket routing **before** truncating the event's fingerprint to u32. Equal valid name byte strings produce the same full hash and therefore the same owner. Quoted and unquoted empty names both hash to zero; escaped names use the exact existing fallback hash. A pair of distinct names with the same low 32 bits can route to the same owner or different owners without merging distinct identities.
- Within each owner the fingerprint is only a lookup key: cache hits check both key and exact name bytes; unpromoted collision chains check bytes; promoted chains use an independently randomized exact-byte-key map. Rows are append-only and cached row indices remain valid through collision promotion. Hash zero is safe because empty cache entries use a row-index sentinel, not a fingerprint sentinel.
- `Event` remains `repr(C)` with fields `u32, u16, u16, u32`: the intended 64-bit target has four-byte alignment and twelve-byte size. `offset`, `len`, group encoding and the long-name sentinel are unchanged. File lengths above `u32::MAX` or unsupported group counts still select the existing sharded fallback before any records or output are processed; the fallback itself is unchanged.
- Producer threads write only their own event vectors; all producer scopes join before reduction. Each owner bucket is reduced by exactly one thread, with a private mutable dictionary and cache, while its source events and memory map are immutable. Shortening the fingerprint adds no shared mutation or unsafe operation. The map remains live for process lifetime, preserving borrowed byte-slice lifetimes.

The review relies on the competition's generated-input contract and the existing name-hash equivalence property; it did not re-prove every baseline parser optimization. It did not perform complete parsing of an actual file over 4 GiB, actual x86 SIMD execution, cgroup-memory proof, or exhaustive concurrency testing. Independent collision and promotion tests are being performed separately by another reviewer.
