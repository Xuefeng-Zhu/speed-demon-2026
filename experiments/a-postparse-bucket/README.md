# Track A per-chunk postparse grouping (not selected)

The candidate groups a parser's completed chunk by local endpoint and hour before joining the other parsers. It counting-sorts each nonempty hour into local endpoint latency slices and records local error counts. After the global exact-byte endpoint rank is known, each hour summary gathers matching slices from all chunks and selects exact nearest-rank percentiles. It does not finalize an hour early and assumes no timestamp ordering. This differs from `a-major-screens/group.rs`, which maintained linked group arenas while parsing every record.

Exact baseline SHA-256 is `16ae5a2e4df27269dbcc2f7b21bb9ad1022081d84e68e5b2c3f5b122a7cb04e2`, candidate is `9a10ada2ee3a4a50d12feb83d1b1f42c645708afba73e45a0e6dd0c2411d2ef3`. On shared native macOS ARM at 12 workers, nine randomized warmed pairs gave candidate/baseline wall 0.061448/0.056206 s, CPU 0.213232/0.214220 s and median native RSS 273,317,888/285,294,592 bytes. A 15-pair repeat gave wall 0.058214/0.059996 s, CPU 0.209643/0.210543 s and median RSS 273,137,664/284,835,840 bytes. All 48 measured full-seed hashes plus four warmups passed. Timing was inconsistent and host activity possible; neither wall result establishes an x86/official speed improvement. RSS includes the file mapping and is not cgroup memory. Raw reports are `report.json`, `repeat.json`.

A temporary Darwin-only MAP_ANONYMOUS flag adjustment passed independent 0/1k/100k/100k synthetic oracle cases, 14 mapped page-end sizes, and a 132,624-group latency grid at 1/2/6/12/64 workers. It also passed empty, 40k all-large-latency, 40k alternating normal/extreme and 87,192-record/2,422-endpoint out-of-order-hour corpora at 1/2/3/7/12/32 workers against the official reference. Actual Linux, x86/cgroup memory and broader independent source review remain unverified. The selected source was not changed; no Mac Docker was used.
