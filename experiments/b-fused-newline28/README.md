# B fused newline and token scanner, current-source rebase (unselected)

`baseline.rs` is the exact selected B source SHA-256 `7d371fe84ce9f0fd9d3c7e6fdf02b6b37e0f1440319c654161b990cf27bb8bf3`; `candidate.rs` SHA-256 `e61211c1764deabdd23b0969fb2a320af2ae3925747568e7845fdcfd459b4b1d`. The unchanged old scanner block and candidate block from `experiments/b-fused-newline/` were mechanically transplanted onto the current source. It fuses newline and token masks in one guarded 32-byte scan instead of `memchr` plus token scanning, leaving exact key comparison, bounded phrase summaries, postings and Boolean evaluation unchanged. No selected code changed.

`python3 experiments/b-fused-newline/independent.py experiments/b-fused-newline28/candidate.rs official/reference/b_index.py` passed 20 boundary-rich corpora at six worker counts (1, 2, 3, 7, 12, 32), including line/token placement across all 32 lanes, long tokens, UTF-8 separators, empty documents and exact reference output. Rust overflow checks were enabled. This runs ARM's scalar classifier and does not exercise actual AVX2 or Linux protected pages. Historical old-source tests are in `experiments/b-fused-newline/README.md` and are not substitutes for current-source x86 tests.

On the shared Mac ARM host, nine randomized full-seed pairs plus warmups compiled equally with `rustc -O -C lto=fat -C codegen-units=1 -C panic=abort` produced candidate/baseline median wall 0.242734/0.237219 s (candidate 2.3% slower), CPU 1.578370/1.521361 s (3.7% higher), and all 20 outputs matched published SHA-256. Raw times and process RSS are in `arm-screen.json`. These results are not official x86 performance or cgroup memory. The preceding historical implementation also screened slower on ARM; no large win is established, so this remains unselected. Actual x86 AVX2 classifier/guard-page tests and paired PGO performance are unmeasured; do not infer that the ARM negative proves an x86 loss. No Docker was used.
