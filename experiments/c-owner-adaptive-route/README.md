# Adaptive owner routing experiment — unfinished

This isolated prototype is **not selected and is not ready for target benchmarking**. It was developed against compact-owner `baseline.rs` SHA-256 `b199855d6c1155decd0c27a329e1a0515681c54011f1b5b11df7752172a3dae4`, not against the subsequently selected salted-owner implementation. `candidate.rs` SHA-256 is `e33bf54a268e06dfbe584225bd50210cf601ed971b9011eee4429feced3b0e1b`.

The prototype routes records using the first eight encoded name bytes and full name length. If the measured bins are sufficiently populated and the largest exceeds 1.5 times their average, it re-partitions all compact events using full Fx hashes before reducing. Exact name equality is retained. The intent is to reduce producer hashing while avoiding an imbalanced reducer when many names share a prefix.

Only compilation was checked: `rustc --edition=2021 -C opt-level=3 experiments/c-owner-adaptive-route/candidate.rs -o /tmp/sd-c-adaptive-route-check` succeeded on the Mac. There are **no correctness, performance, Linux/x86, memory, or independent-review results for this exact candidate**. The copied test scripts in this directory have not been adapted or run against it and must not be treated as evidence. No official run was made.

Before considering this approach, independently review exact routing/equality, concurrency, fallback before output, offsets, long names and group limits. Test both routing branches with duplicate names, deliberately identical prefixes and lengths, full-hash collisions, varied worker counts, reference/oracle data and forced size-limit fallbacks. The re-partition branch holds old and new event buffers concurrently, increasing peak memory; measure it on the target. Compare against the *current* selected salted-owner source, which differs materially from this baseline. A deterministic full-hash collision can still concentrate work; this design inherits that issue from its compact-owner baseline. Preserve all existing competition constraints.
