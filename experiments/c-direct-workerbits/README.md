# Direct names with worker-private bitmaps — unselected

The baseline is selected fused owner SHA-256 `6e12627e96f0a0433e567413ccacc1a5d7fdf2de8f4781a3f826c260499783dd`; candidate `f2b9e6bc60da6fd12778580bd7cc9371b21a269f49758df76f07af82894c2164` uses one million stable direct name slots. Each winning node contains disjoint `UnsafeCell<u64>` words for each parser worker. A parser is the only writer to its own four words; after all parser threads join, separate scanners OR the words to count distinct names by group. Other names sharing a slot use an independently salted, locked exact-name fallback, whose counts are **added** to the scanned results. Nodes are intentionally retained until process exit. The direct path is gated to at most 16 workers and 256 total groups; other inputs retain the selected owner/large-file paths.

Independent static review found no defect conditional on unique stable worker IDs, publication via release/acquire, fixed cells with no whole-slice mutable references, and join-before-read. Tests included 120 mixed reference cases, 20 long-name/forced-fallback cases, 27 concurrent reference cases, 20 group cases, synchronized one-slot races with fixed and racing winners and 1/2/7/16 workers, and 24 additional independent end-to-end checks at group/worker thresholds. Actual OS data-race instrumentation, true >4-GiB parsing and x86 have not been performed.

At 16 workers and 1,048,576 claimed nodes, bitmap payload alone is at most 512 MiB, plus an 8 MiB pointer directory and approximately 32 MiB node metadata on a 64-bit host. Collision maps, copied names, input mapping (up to 4 GiB at the compact gate), aggregates, thread stacks, allocator metadata and transient peaks are additional; this is **not a complete 8-GB worst-case proof**. Adjacent worker slices can also false-share cache lines.

One native ARM 15-pair full-seed screen produced candidate/baseline median wall 0.09540/0.07477 s, CPU 0.64076/0.46164 s, and native RSS roughly 245/284 MB. All 32 hashes matched. This shared-machine run shows a substantial speed regression, not x86 or official performance. Raw samples are in `arm-report.json`; do not promote on this evidence.
