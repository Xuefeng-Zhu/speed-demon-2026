# A exact 16-byte endpoint hint (unselected)

`baseline.rs` SHA-256 `4af40353f517f566217b0f882ec25d8002f61d211dcc479c53f8a1dd5de7ed88` is the exact selected compact-record source. `candidate.rs` SHA-256 `e37df2acccdfed05d207625a3550bfa38953cb5a233f7c534cd32c582f566b0c` uses a 4,096-slot per-parser hint keyed by the normalized first 16 endpoint bytes. A short endpoint (<16 bytes) is matched exactly by the masked prefix and length; a longer one requires equal first 16 bytes, exact remainder comparison and its stored-length delimiter. An advisory miss invokes the original full-hash table. Local IDs remain stable when the table grows. The zero-padded mapping and ≤125-byte endpoint bound support these guarded accesses. Identical first prefixes can thrash the hint and cause extra work; exact equality prevents changed output.

Two 15-pair shared native macOS ARM full-seed batches after two warmup pairs each had candidate/baseline medians 0.037400/0.037336 s and 0.039286/0.038908 s. CPU medians were 0.189516/0.194643 s and 0.187640/0.192504 s. Every one of 68 executions matched the published full-output SHA-256. `arm-a.json` and `arm-b.json` preserve raw samples; temporary native builds changed Linux MAP_ANON to Darwin only. The slightly lower CPU did not produce a wall win; process RSS and native ARM timing are not official cgroup or x86 measurements. No Mac Docker was used.

The candidate passed the existing 0/1k/100k/100k reference suite and compact record stress (empty, 40k all-escape, 40k alternating, 87,192 records over 2,422 endpoints at 1/2/3/7/12/32 workers). `collision-test.py` compares 40,000 records against the official reference at 1/2/7/12/32 workers for both candidate and a temporary variant forced to use a single hint slot. It includes 2,300 endpoints sharing the first 16 bytes, 1/7/8/9/15/16/17/31/32/63/64/125-byte boundaries, changing statuses, and escape latencies. These are native Darwin-map tests, not Linux x86 protected-page tests. Independent review is pending. Because no wall gain appeared, it is unselected and has not received target or official evaluation.

Independent static review found no concrete valid-input defect in prefix equality, length-16 delimiter handling, longer suffix checks, stable IDs through table growth, or the existing 4 KiB mapped padding assumption. The hint introduces no new unsafe operation. The review did not run separate tests or inspect actual x86 guarded-page behavior. Each 4,096-entry hint array uses 96 KiB per parser on a 64-bit target, before allocator overhead.
