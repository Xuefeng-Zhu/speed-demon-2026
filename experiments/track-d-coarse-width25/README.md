# D coarse-bucket width sweep — isolated, preliminary

This experiment varies only `BUCKET_SHIFT` in `track-d-coarse-buckets24/candidate.rs` (SHA-256 `2a2a325a1c87e4bc68c260e0d80353e0b8f1f9a7b5be81b1ffeaaede6d813f9d`). It does **not** alter the selected Track D implementation (batch16 SHA-256 `7fd333be25133a78264cb4b84441de46d4c8bcbfd73914af23761f23d8c47f17`). Exact distances, conservative bucket bound, the fixed queue capacity and exact fallback are unchanged. Correctness reasoning for any shift relies on monotonic nonnegative relaxations and re-enqueuing every strict decrease; the existing 8 GiB hidden-data parent-cgroup limit remains unproved.

A clean single warmup and seven randomized full public seed-1 rounds on shared macOS ARM tested shifts 3–10. All 64 output hashes matched the published seed-1 hash. Median wall seconds were: shift 3: 0.234432, 4: 0.237710, 5: 0.223916, 6: 0.226826, 7: 0.246155, 8: 0.283621, 9: 0.348524, 10: 0.540021. Shift 5 was ~1.3% faster than shift 6 in this screen; this is a small single-batch difference, not a target-machine result. CPU medians and raw observations are in `arm-screen.json`. Larger buckets clearly increase repeated relaxation cost on this seed. Shift 5 needs repeated paired benchmarks, forced-exhaustion/zero-cycle and independent oracle tests, and actual x86/cgroup verification before consideration. No Docker was run on the Mac.

Run `python3 experiments/track-d-coarse-width25/screen.py --data /tmp/speed-d-full --build-dir /tmp/d-width25 --report experiments/track-d-coarse-width25/arm-screen.json --runs 7` in an exclusive native timing window. Output reports process RSS rather than cgroup peak. The temporary data directory is local only and is not part of this experiment.

A fresh randomized 15-pair shift-5/shift-6 repeat gave median wall 0.228667/0.232949 seconds (shift 5 about 1.84% faster) and CPU 1.538259/1.595677 seconds (about 3.6% lower); all 32 hashes passed. Data and native RSS are in `arm-repeat.json`. This remains a small ARM-only change. `verify.py`, `adversarial.py` and `long_bucket.py` are adapted from the shift-6 experiment to use `shift5.rs`; the long-cycle edge weights are bounded by 31 to stay in a single shift-5 bucket. All three suites passed for shift 5: seven forced capacities each passed 16,000 random and 36,864 exhaustive queries plus cutoff, packed/wide 2^21 boundaries, maximum-weight chain and 6,000 repeated queries. Ten dense directed/zero/parallel graphs at three caps exercised 2,871,513 repeat expansions and 622,037 key inversions. The 8,191-node same-bucket zero cycle forced capacities 2 and 16 to exhaust and correctly rerun exact fallback.
