# C row-cache capacity screen — unselected

`baseline.rs` is the exact 32,768-slot row-cache source, SHA-256 `76b341e2b7e880fe4ceeee220206a63b48cd247bba4448aa7991a7ad825e8dd2`. Each candidate changes only `CACHE_SLOTS` to 8,192, 65,536, 131,072 or 262,144. Each entry is 16 bytes on 64-bit systems, per active owner; larger caches increase their memory footprint. Full 64-bit hash and exact bytes are still checked on every hit; no selected code is modified by this experiment.

Using generated public full seed 1, four randomized 11-pair warm-cache native ARM batches gave candidate/baseline median wall seconds 0.09994/0.09276 (8,192), 0.07611/0.07520 (65,536), 0.07563/0.07270 (131,072), and 0.08792/0.08362 (262,144). A further 15-pair 65,536 batch gave 0.07104/0.07327 seconds, with CPU 0.4355/0.4368 seconds and native process RSS approximately 278.1/274.0 MiB. All 128 executions including warmups matched the full-data output hash; individual wall/CPU/RSS samples are in JSON. This shared-ARM screen is variable, not x86 or official performance. No broad alternate/collision tests were performed on the variants. The 65,536 results are inconsistent and the other sizes were slower, so no target recommendation or speed claim is made.
