# Independent C row-cache review

The reviewed candidate `../c-fused-owner-rebase/rowcache.rs` has SHA-256 `76b341e2b7e880fe4ceeee220206a63b48cd247bba4448aa7991a7ad825e8dd2`; the exact selected baseline has SHA-256 `6e12627e96f0a0433e567413ccacc1a5d7fdf2de8f4781a3f826c260499783dd`. This is an isolated experiment, not selected code.

The only algorithmic change is a direct-mapped owner-local cache of `(full hash, row)`. A hit requires the full hash and exact input bytes to match. Entries are append-only; promoting a long full-hash collision chain into the salted exact-name map does not invalidate row indices. Replacement cannot alter dictionary entries or group bits. Identical name bytes produce the same full prehash, including the two empty-name encodings. Each owner builds and mutates its own dictionary in a single reduction thread; no cache state is shared. This change introduces no unsafe code and does not modify the non-packed fallback.

`python3 experiments/c-rowcache-independent/run.py` verifies the candidate SHA, appends `test-tail.rs` to an unmodified temporary source copy, and runs a Rust test compiled with `-O`, overflow checks and debug assertions. It passed 8,000,000 `(name, group)` operations against an independent `HashSet` oracle across 1, 63, 64, 65, 240, 241, 256 and 257 groups. Cases include hash 0, hash `u64::MAX`, all-equal full hashes with promotion, distinct full hashes sharing one cache slot, mixed promoted chains sharing one slot, independent allocations with equal bytes, empty names and trailing spaces. It checks cache indices and rows after each test. Result on native macOS ARM: **1 passed**, 0 failed.

The new fixed cache costs 524,288 bytes per active owner on a 64-bit target, plus allocator overhead; 12 simultaneous owners imply about 6 MiB additional payload. It is allocated only on the first `see` for an owner. This review did not establish target x86 performance or the full process/cgroup memory maximum, did not exercise the real x86 SIMD path, and did not test parsing a complete file larger than 4 GiB. The underlying fallback and parser were unchanged by this candidate.
