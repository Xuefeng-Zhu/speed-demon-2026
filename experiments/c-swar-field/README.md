# Track C guarded SWAR delimiter scanner (not selected)

The baseline is the selected CRLF-synchronized source (SHA-256 `3e181c76981348a96b48470844ee0f8988847d32164ff935a211024861c86ad4`). The candidate uses guarded unaligned 8-byte loads and the zero-byte arithmetic trick to find the next quote or comma, then retains the original escape handling. This differs from `c-fused-scan`, which calls libc `memchr` and changes numeric parsing. The first detected matching byte is valid even where subtraction borrow creates later false-positive bits. It is unselected.

Two randomized native shared ARM screens measured candidate/baseline median wall 0.14138/0.15268 s (7 pairs) and 0.13951/0.15482 s (15 pairs), CPU 0.74218/0.80585 and 0.77181/0.83888 s respectively. In a direct 11-pair comparison against the prior fused scanner, SWAR/fused medians were 0.15556/0.15327 s wall and 0.79424/0.74285 s CPU. All 72 full executions including warmups matched the published hash. Shared-host timing is noisy and not x86 or official; the previously fused variant's x86 comparison was inconsistent. No target gain is established.

The exact candidate passed 24 mixed corpora at 1, 2, 3, 7 and 16 workers, 15,145,280 overflow-checked scalar delimiter comparisons, 76,924 guard-page comparisons on macOS, and 19,547 parsed field cases against the selected field implementation. The property harness also checked 20,200,029 numeric comparisons because that helper remains unchanged. `property.py`, `guard.py`, `independent-verify.py` and raw JSON reports preserve those checks. The latter reuses `experiments/c-fused-scan/property-main.rs`. No Mac Docker was run.
