# D query-order screens (not selected)

The exact balanced-frontier baseline is the selected Track D source at commit 23ffdfc. Each variant changes only the order in which independent queries are assigned to workers; answers are stored in the original query slots. `degree-desc` and `degree-asc` sort by the product of source out-degree and target in-degree, `min-desc` by the smaller degree, and `reverse` reverses input order. The degrees are computed from the input graph at runtime; no cached answers or input recognition is used. No variant is selected.

Every full seed-1 hash matched in one warmup and four randomized measured runs per variant on a shared ARM Mac. Median wall times were baseline 0.4127 s, degree-desc 0.4472 s, degree-asc 0.4265 s, min-desc 0.4712 s, and reverse 0.4061 s. Samples varied substantially with host activity and do not establish a target-machine win. All four variants and the baseline matched an independent Dijkstra oracle on 80 random directed graphs (16,000 queries each). See `report.json`. Process RSS is not cgroup memory.

A prior single instrumented full-seed profile (`experiments/track-d-frontier-bias/query-times.txt`) yielded Spearman correlations −0.058 to +0.006 between query time and individual, minimum, sum or product endpoint degrees. A simulated 12-worker makespan was 0.1975 s in input order and 0.1945 s in an unavailable oracle longest-first ordering. Two-hop degree features had correlations −0.056 to +0.013; prioritizing nontrivial queries identified by direct/two-hop adjacency saved only 22–62 microseconds in this simulation, before feature-computation cost. This single noisy instrumented profile does not predict target performance. `features.py --data /path/to/full-d` and `neighbor-features.py --data /path/to/full-d` reproduce the analysis; input data is generated separately.

For controlled native comparison, run `python3 experiments/track-d-query-order/compare.py --data /path/to/full-d --report /tmp/d-query-order.json`; it compiles offline with matching Rust flags, randomizes order and verifies every full output hash. Recheck target CPU flags and cgroup peak independently. No Docker was used.
