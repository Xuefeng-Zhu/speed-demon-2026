# Direct B postings experiment (not selected)

Against the pre-AVX eight-byte scanner baseline (source SHA d171f59bee7ad02d8f5bb1b9d67315b622a24e85340512269dbbad6133379fda), this experiment replaces the temporary term stream and CSR counting-sort with per-worker `Vec<Vec<u32>>` postings built directly while scanning each document. It leaves phrase summaries and exact set evaluation unchanged. Five randomized shared-ARM pairs after one warmup all matched the full seed-1 hash; candidate median wall 0.433228 s vs baseline 0.377321 s, CPU 2.5418 vs 2.0551 s. Maximum native process RSS was about 444 MB candidate vs 537 MB baseline. These are contended Mac process measurements, not official x86/cgroup scores; the slower candidate was not promoted. See report.json and use the comparison driver in `experiments/b-rust-lengthhash/compare.py` with equivalently compiled binaries and independently generated full data.
