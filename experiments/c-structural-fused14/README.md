# C quote-parity structural scanner — unselected

This isolated candidate is based on exact selected dual-lane source `baseline.rs` SHA-256 `8249f318e26050cc1a12f2be091344bf431ceb862665a3312bb29a92e140057d`; `candidate.rs` SHA-256 is `d66d963c2388961af0117f40d2938c79df4004eace5a0087b1898af8d66fbd70`. It is not selected or pushed. The compact path scans each CRLF-aligned lane with 32-byte quote/comma/LF structural masks. Quote parity identifies outside-quote delimiters, including doubled quotes and pairs across block boundaries. Raw name/note byte lengths are derived from the count of quote bytes in each field, and names use the existing exact hash. Owner routing, full-byte equality, long-name sentinel, file/group fallback, aggregates and output are unchanged. It relies on official §2.2's generated-input guarantees, including CR only as a CRLF terminator; it does not claim unrestricted CSV §2.1 support.

The classifier compiles its AVX2 path only when the target guarantees AVX2; all other targets use scalar classification. Every load is bounded to the synchronized chunk. This parser scans numeric bytes as well as text and hashes each name separately after identifying its span, so the structural pass adds work relative to the baseline's fused name scan. The ARM scalar path and actual x86 AVX2 path have materially different costs.

Local macOS ARM validation:

- `run-property.py` passed 308,400 randomized quote/parity/span sequences and 16,416 valid quoted-field comparisons against the baseline parser. `guard.py` passed over 4,000 page-edge field cases, including escaped pairs crossing 31/32-byte boundaries.
- `reference.py --source ... --seeds 24` passed 120 mixed reference comparisons across 1/2/3/7/16 workers. `lane-coverage.py` passed 70 actual-source ID/reference cases covering collapsed cuts, both scalar tails, BOMs, embedded LF, and a 100,000-byte sentinel name spanning cuts. The fixture remains below Python reference CSV's default 131,072-byte field limit and does not imply any format length limit.
- `forced-collision.py` passed five all-hash-zero references with actual exact-name collision promotion and a 70,000-byte sentinel. `forced-fallback.py` passed both forced file-length and group-count fallback gates across five worker counts; `gate.py` tested 4 GiB/group arithmetic boundaries. No full >4 GiB parsing was tested.
- `asm-check.py` cross-compiled an extracted exact helper for Windows x86-64-v3 and observed AVX2 compare/movemask instructions. It is **code generation only**, not actual Linux x86 execution, not a guard-page execution, and not a speed result. The `--avx2` test options must be run only on verified compatible x86-64-v3 Linux hardware.

On a shared macOS ARM host, after warmup, three randomized paired full public seed-1 executions per source all produced the published output hash. Median wall baseline/candidate was 0.068396/0.105888 seconds; median CPU was 0.394327/0.700923 seconds; process RSS was roughly 292/295 MB. The scalar candidate was ~55% slower in this short native screen. `arm-screen.json` contains the individual samples. This does not measure the x86 AVX2 implementation, cgroup peak, or official score; it does not establish a target speed gain. Given the regression and missing x86 evidence, no target test or promotion is recommended on current evidence.

To reproduce after independently providing data (never remove unrelated data), run `python3 experiments/c-structural-fused14/run-property.py`, `guard.py`, `reference.py --source experiments/c-structural-fused14/candidate.rs --seeds 24`, `lane-coverage.py`, `forced-collision.py`, `forced-fallback.py`, `gate.py`, then compile both sources with identical release flags and use `compare.py --baseline <binary> --variant <binary> --data <generated-full-c> --runs 3 --report <path>`. `asm-check.py` is an optional Windows-target codegen check only. On a Linux x86-64-v3 host, confirm CPU support first and add `--avx2` to the test runners; compile with `-C target-cpu=x86-64-v3`. No actual Linux AVX2 guard, >4 GiB full-file parse, hidden-seed or official cgroup result is claimed. No Mac Docker was used.
