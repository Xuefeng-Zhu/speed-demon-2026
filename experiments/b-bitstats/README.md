# Dense bitmap result summaries (experimental)

`baseline.rs` is the exact selected B source at `e88ee2c`, SHA-256 `d0f0d79f3f646275d2e33ef34659eba5bca56fb2bb16504025f10a800e88cc49`. `candidate.rs` SHA-256 `322cc95ee08cf6d4abc5e1b52240753f66c7eaf89ab669cb6d72b0a8487dc458` summarizes each Boolean result word with popcount: sparse words enumerate bits, while dense words sum bit positions through six bit-plane popcounts. It still gathers the first ten IDs in ascending order. The AVX2 tokenizer, bounded phrase summaries and bitmap cap are unchanged. The baseline's now-unused `part` helper was removed. This candidate is not selected.

Two shared native ARM screens matched all 48 full-data outputs. Seven-pair medians were 0.25845 s candidate vs 0.26666 s baseline; a 15-pair repeat was 0.25871 vs 0.26921 s. Those screens still included an unused `part` helper; the cleaned candidate then matched two more full pairs (`mac-clean-smoke.json`). Shared-host activity and the ARM scalar tokenizer mean these are not target x86 or official scores. The comparator records native wall/CPU/RSS; Linux process RSS is KiB, not cgroup memory.

Independent overflow-checked testing compared the exact aggregation block with scalar enumeration for every 16-bit mask at four positions, edge masks and 100,000 random multiword sets. A separate mask identity test checked 65,536 patterns and 200,000 random words. Forced 1/2/7/32-worker builds passed 80 dense/mixed reference comparisons around 64-bit word and 2,048-document boundaries. Additional 40 mixed corpora, distributed top ten, >1 MiB boundaries and 250,000-document/19,000-duplicate-phrase stress passed. Test-only always-dense and always-sparse branches, plus zero- and 256-byte total bitmap caps, also passed overflow-checked fuzz and dense references. Per the documented full workload, N≤250,000, so chunk-local count/base fit u32 and the global sum N(N−1)/2 fits u64.

From the repository root, run `python3 experiments/b-bitstats/independent-dense.py`, `python3 experiments/b-bitstats/mask-review.py` and `python3 experiments/b-bitstats/forced-paths.py`. In the experiment directory, `python3 verify-property.py && rustc --test --edition=2021 -C opt-level=2 -C overflow-checks=yes property.rs -o /tmp/b-bitstats-property && /tmp/b-bitstats-property` checks the exact compiled aggregation block. For native full-seed timing, build both Rust files with identical release and target CPU flags, then run `python3 experiments/b-bitstats/compare.py --baseline /path/to/base --candidate /path/to/candidate --data /path/to/full-b --runs 15 --report /tmp/b-bitstats.json`. Use separately generated data and serialized runs; target AVX2 and warmed cgroup checks remain necessary.
