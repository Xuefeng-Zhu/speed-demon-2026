# Parser-local exact pair filter (unselected)

`baseline.rs` is the selected two-lane C source SHA-256 `8249f318e26050cc1a12f2be091344bf431ceb862665a3312bb29a92e140057d`; `candidate.rs` is `181f4b8e2d196f80b0b2cfef21834635f0ace2dedd0d6fcaae4a2e227967d5e5`. Each parser has a 16,384-entry direct-mapped cache of previously emitted `(name, group)` events. A hit requires equal full hash, group, length and immutable name bytes; hits skip redundant owner events, while collisions replace and emit. Very long sentinel names always emit. All record aggregates still include every record; owner reduction and the non-packed fallback remain unchanged. This is an isolated hypothesis, not independently reviewed, and it relies on the inherited generated-input assumptions.

After warmup, nine randomized paired full seed-1 native macOS ARM executions per binary produced the published output hash in all 20 runs. Median wall was 0.067144 s candidate versus 0.066442 s baseline; CPU 0.410688 versus 0.400119 s. Raw measurements are `arm-screen.json`. A separate instrumented run with an atomic counter reported 17,830 suppressed events from 3,320,000 records (0.54%) and also matched the output hash. Instrumentation changes runtime and is not a performance result. Uniform name sampling in the public workload makes a small hit rate plausible, but the single-seed count is not a holdout guarantee. These shared-host ARM measurements are not x86 or official cgroup results. There is no alternate-reference, forced-hash-collision, guard-page, concurrency, >4 GiB or independent proof for this experiment. The result does not justify target testing or promotion; selected code remains unchanged.

To reproduce the nonofficial full-data screen, build both source files with `rustc --edition=2021 -O -C lto=fat -C codegen-units=1 -C panic=abort` and run `python3 experiments/c-fused-owner-rebase/compare.py --baseline /path/to/base --variant /path/to/candidate --data /path/to/full-c --runs 9 --report /path/to/report.json`. No Mac Docker was run.
