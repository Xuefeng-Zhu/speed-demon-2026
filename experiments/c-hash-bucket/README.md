# C prehashed collision-bucket dictionary (not selected)

Baseline is selected parser source SHA-256 `f71a22c0642250010d967cfb493fbfb95bab01f1c3e4dedac0b93fb2987e80ef`. Candidate hashes each name once and uses a sharded identity-hash `HashMap<u64, row>`; full-byte names and group bits are stored separately. Up to eight different names sharing the same 64-bit hash form an exact collision chain; denser chains promote into a separately seeded exact-name map to avoid unbounded quadratic probing. This differs from the older prehashed-name-key HashMap and the linear-probe inline table. The prototype remains unselected.

Eleven randomized warm full-seed shared ARM pairs plus warmups matched all 24 full hashes. Median candidate/baseline wall was 0.10891/0.10915 s and CPU 0.66980/0.68169 s; native RSS roughly 228 MB versus 226 MB. Differences are small, are not x86 or official scores, and do not support a significant speed claim. See `arm-report.json`. No Mac Docker was run.

Independent exact-source tests passed promotion at 8→9 distinct equal-hash names, multiple promoted hashes, duplicate/empty names, group-bit boundaries through 512 and a 50,000-name forced-full-hash collision family. An independent review found no correctness defect, but an outer identity-hash map can cluster distinct hashes with matching bucket/control bits. A synthetic 64,000-u64 stress took 3.405 s identity versus 2.18 ms salted on the shared ARM machine. Such Fx hash values have not been shown to arise from legal generated names. `independent-test.py`, `independent-tail.rs` and `lowbits-stress.rs` preserve the tests; this performance risk and the near-tied result preclude promotion.
