# C local intern cache with atomic group bits (not selected)

Baseline is the exact selected CRLF implementation SHA-256 `3e181c76981348a96b48470844ee0f8988847d32164ff935a211024861c86ad4`; candidate SHA-256 `040e3c7936fce22318fc698ae5c0d3dca162ceb71b493af24625f7ba126e8d60`. Each parser caches borrowed exact names in its own map, while shared shard maps intern a single `Arc` with atomic group-bit words. The first atomic bit-set counts the distinct name/group. This aims to avoid repeated global mutex acquisition, but adds local lookups and atomic operations. It is an isolated prototype, not selected.

Seven randomized full seed-1 pairs following warmup all matched the published output SHA-256. On the shared native ARM Mac, median candidate wall was 0.189528 s versus 0.126188 s baseline; median CPU was 1.229798 versus 0.807021 s. Maximum native process RSS was approximately 273.9 MB versus 226.1 MB. See `report.json` for samples. Other activity may affect timing; process RSS includes mapped input and is not the official cgroup peak. These results are not x86 or official scoring. No alternate-input or adversarial collision checks were run because the candidate was markedly slower. No Mac Docker was used.

Compile with identical `rustc --edition=2021 -O -C lto=fat -C codegen-units=1 -C panic=abort` flags and compare using `python3 experiments/c-rust-dictionary/compare.py --baseline /path/to/base --variant /path/to/candidate --data /path/to/generated-full --runs 7 --report /tmp/c-local-atomic.json`. Generate inputs separately; hashes are for output verification only.

A second screen rebased the earlier prehashed borrowed-key idea onto the exact current 1024-shard CRLF baseline: `prehashed-rebased.rs` SHA-256 `c7db771943639e41a8d9e10c5d174cbe56227db65f4abf07d624b98de2fe634a`. Each shard uses an identity hasher over a precomputed hash while retaining exact name bytes in equality, avoiding the second name hash. Nine randomized full seed-1 pairs after warmup all matched the official hash; median candidate wall was 0.140258 s versus 0.125459 s baseline, and median CPU 0.792110 versus 0.759113 s. This shared-ARM screen is slower and nonofficial; no broad alternate-data or forced-collision checks were run. See `prehashed-rebased-report.json`.

A third screen (`fxwide.rs`, SHA-256 `167c75a386de571fd8bcf4f0fbd95f84571680cb380642f4047ddd8cf32bbe62`) replaced the Fx hasher's bytewise chunk folding with little-endian 8-byte loads and a zero-padded tail, retaining the exact same hash calculation. Nine randomized full seed-1 pairs following warmup all matched the official output hash. Contended ARM Mac medians were 0.198189 s candidate and 0.140786 s baseline (CPU 0.853164 vs 0.817258 s), with wide ranges; the last four low-load-looking pairs were also near tied. Results in `fxwide-report.json` show no defensible gain, so it remains unselected. This is not an x86 or official score; no alternate-input test was undertaken.
