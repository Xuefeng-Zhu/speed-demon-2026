# C owner dictionary reuse (unselected)

`baseline.rs` is the dynamic-partition C trial, SHA-256 `bcd4d7715bffd8a3dc062cad6e7aa0886a96d659fcc9170735c4d4d123f67eae`; `candidate.rs` is SHA-256 `d067eca411adf23875aaf4edb8394894536e9198a3acd04a24e72c7dbfac903d`. It keeps one owner-local dictionary per reducer thread and clears its heads, cache entries, names, group bits and promoted maps before each subsequently claimed partition, reusing allocated capacities instead of dropping the dictionary. The owner routing, hash, exact byte equality, parsing and large-input fallback do not change. Resetting every cache slot before the next partition prevents stale row IDs from being reused, and clearing the group-bit vector before resize resets membership.

The candidate matched 24 generated reference corpora at 1, 2, 3, 7 and 16 workers, plus eight corpora at those worker counts with all names forced to one hash. A separate overflow/debug-checked test exercised 400,000 insertions across 100 explicit reset phases, group counts 1/63/64/65/241/257, repeated names, direct-cache collisions and forced full-hash collision promotion. `python3 experiments/c-dynamic-dict-reuse/verify.py` reproduces those checks. Tests are on native ARM and do not establish x86 SIMD, full >4 GiB, adversarial allocator/cgroup limits, or hidden-data correctness.

Two serialized randomized full public-seed 15-pair native ARM screens (plus warmups) had baseline/candidate median wall `0.067162/0.066992 s` and `0.068027/0.067749 s`, and CPU `0.424974/0.423697 s` and `0.424581/0.422759 s`; median process RSS was roughly 297.6/295.4 MB and 298.1/295.0 MB. All 64 full output hashes matched. See `arm-a.json` and `arm-b.json` for individual observations. The wall difference is below 0.5% and does not establish a practical gain; the candidate remains unselected and is not recommended for a target slot without a new hypothesis. It has not received independent review or official testing. No Docker was run on the Mac.
