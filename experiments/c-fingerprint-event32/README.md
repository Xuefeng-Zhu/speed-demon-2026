# C 12-byte fingerprint events — unselected

`baseline.rs` is exact selected C source SHA-256 `8249f318e26050cc1a12f2be091344bf431ceb862665a3312bb29a92e140057d`, and `candidate.rs` SHA-256 is `78d9b4209daf59f414bcf327f1ec955df91b1b334a28cedfbdbe966a598cfc43`. The full 64-bit exact name hash still selects each owner partition, ensuring equal names reach the same owner. Each event stores only the low 32 bits of this hash, reducing `Event` from 16 to 12 bytes; the owner passes this fingerprint to the existing exact-byte dictionary. A fingerprint collision cannot merge distinct names because the existing dictionary compares full encoded bytes and promotes a long equal-hash chain to a randomized exact-name map. Routing, long-name sentinel, parsing and file/group fallback are unchanged. This is a rebase of the older unselected `c-owner-salted32` concept onto the current parser and owner cache, not a claimed speed win.

Independent read-only review found no concrete defect in full-hash routing, low32 cache checks, exact collision promotion or sentinel handling. Truncation can increase collision chains and promotions; it does not bound worst-case time, allocation or parent-cgroup memory.

Two coordinated native ARM full-seed paired screens after warmup gave candidate/baseline median wall 0.064678/0.066767 s (11 pairs) and 0.062846/0.064297 s (15 pairs), and CPU 0.389394/0.393464 and 0.392367/0.398751 s. Median native process RSS was 276,135,936/292,814,848 and 277,069,824/294,764,544 bytes. All 56 output hashes matched. These shared-machine results are modest, nonofficial and not an x86 or cgroup measurement.

`c-two-lane-parse/reference.py --source experiments/c-fingerprint-event32/candidate.rs --seeds 24` passed 120 mixed reference comparisons. `forced-collision.py` forced all event fingerprints and routes to zero, checked actual promotion and long sentinel against the reference across five worker counts. `forced-fallback.py` passed both pre-output fallback gates across five worker counts. `property.py` passed 50,000-name forced-fingerprint promotion, repeated cache evictions, exact 65,535-byte and longer sentinel boundaries, and a deterministic search for two distinct actual full hashes with the same low32 fingerprint and owner, followed by exact membership checks. `guard.py` passed protected-page field parsing on ARM. Actual Linux/x86 AVX2 and guard, official score, complete >4 GiB input, and cgroup memory remain unverified. No Docker was run on the Mac.
