# Track C guarded SWAR integer parse (not selected)

The selected baseline SHA-256 is `3e181c76981348a96b48470844ee0f8988847d32164ff935a211024861c86ad4`. The isolated candidate applies an unaligned guarded eight-byte load, comma detection and decimal digit pairing only to the unquoted positive `id` and `region_id` columns; longer and near-end cases use the original scalar function. Amount and all other parsing/aggregation are unchanged. It computes results from the input and does not embed dataset answers. This differs from `c-fused-scan`, which specializes amounts but uses scalar `id`/`region_id` parsing. It remains unselected.

In nine warm randomized full-seed ARM pairs, median candidate/baseline wall was 0.18014/0.18736 s and CPU 0.84173/0.90469 s. A 15-pair repeat was very heavily contended and reported 0.40783/0.42749 s wall and 0.93160/0.97648 s CPU. Every full output matched the expected hash (50 executions including warmups). Raw JSON retains each sample. The small differences and heavy contention do not establish x86 or official speed benefits; more meaningful performance work takes priority.

The candidate passed 24 independent mixed CSV corpora at five worker counts against the official reference, 10,001,599 overflow-checked comparisons including every id 1–9,999,999 plus 8-digit fallback and aligned suffixes, and 36 protected-page edge checks on macOS. `property.py` and `guard.py` extract the exact functions from `candidate.rs`. The end-to-end source still relies on §2.2's CRLF boundary and name restrictions. No Docker was run on the Mac.
