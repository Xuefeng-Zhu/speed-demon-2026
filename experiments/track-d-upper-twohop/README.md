# Capped short-path upper bound (experimental, not selected)

This isolated candidate starts bidirectional Dijkstra with the cheapest runtime-discovered one- or two-edge path through matching forward and reverse neighbors, if present. Such a path is a valid upper bound, not necessarily the answer. A zero bound is immediately exact. The precheck executes only when each endpoint degree is at most 64 and their product is at most 64, so legal high-degree hubs cannot cause quadratic blowup. The baseline is selected hugepage-hint D at bc902c7. No input-derived answers or precomputation are stored.

The final capped build passed the published full seed-1 hash every run, 16,000 independent random graph queries, 36,864 exhaustive three-node queries, the maximum-size max-weight chain, 6,000 repeated/unreachable queries and four high-degree/skewed oracle graphs. Nine paired shared ARM native measured runs (`report.json`) gave median wall 0.2860 s vs 0.2912 s baseline, CPU 1.8288 vs 1.8404 s. A separate eleven-pair repeat (`repeat.json`) gave 0.27728 vs 0.27766 s wall, CPU 1.8239 vs 1.8373 s, peak process RSS 535,035,904 vs 534,937,600 B. Host activity may affect results; these are neither x86 nor official cgroup measurements, and no significant wall gain is established. No Mac Docker was used.
