# Exact per-parser note memo — unselected

Baseline is byte-identical to selected `track-c/src/main.rs`, SHA-256 `8249f318e26050cc1a12f2be091344bf431ceb862665a3312bb29a92e140057d`; candidate SHA-256 `8686a2fc8641d1b06b84a7be5f3cac773bba296a740ee7a87fe1c318a6a88fd1`. Each compact-path parser has a bounded 32,768-slot direct cache. It hashes the first eight raw input bytes, then verifies the entire previously parsed raw note field **including its trailing comma** byte-for-byte before using the previously decoded length and advancing the cursor. A miss invokes the original `field` function and stores its result; short file tails use `field` directly. Both parser lanes share only that parser's cache. This relies on valid generated-input CSV as specified in §2.2; it does not assume any particular note values, pool, or distribution for correctness. Inputs beyond existing compact gates continue to use the old fallback.

An independent static review found no concrete defect: equality of the complete raw field and delimiter makes the original deterministic parser produce the same decoded length and boundary; cached offsets come from valid parsing of the same immutable map. The 32,768 slots use approximately 768 KiB per parser, or ~9 MiB for 12 parsers before allocator/cgroup overhead. A nearly equal long field may be compared and then parsed, increasing work. Finite tests do not prove all-input correctness or an 8 GiB cgroup bound.

`python3 experiments/c-fused-namehash/reference.py --source experiments/c-note-memo31/candidate.rs --seeds 24` passed 24 randomized mixed CSV corpora across 1, 2, 3, 7, and 16 workers (120 comparisons), including quoted and unquoted empty fields, commas, escaped quotes, multiline notes, long values and unknown regions.

A coordinated shared-Mac ARM screen with `rustc --edition=2021 -O -C lto=fat -C codegen-units=1 -C panic=abort` and `python3 experiments/c-rowcache-dynamicparts/compare.py --baseline /tmp/sd-c-note31-baseline --variant /tmp/sd-c-note31-candidate --data /tmp/sdc-full --runs 9 --report experiments/c-note-memo31/arm-screen.json` passed the published full-seed output hash in all 20 warmup and timed executions. Median wall candidate/baseline was 0.073335/0.065417 s (+12.1%); CPU 0.453686/0.400801 s (+13.2%). Shared-host ARM timings and process RSS are not official or x86 measurements. The candidate is unselected due to the substantial regression; actual x86/AVX2, protected-page cases and additional adversarial stress were not performed. No Mac Docker was used.
