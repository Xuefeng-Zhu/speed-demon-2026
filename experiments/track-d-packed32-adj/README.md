# D compact adjacency with large-weight fallback (unselected)

`meeting.rs` is an isolated candidate based on the exact selected `baseline.rs` (SHA-256 `ac9674a11b90244c63a518ee94eb7a9547353540ff564672aaa128ac4851a2ea`). Candidate SHA-256 `793d13729fe4dabe2a1ed272fef78e19567456676ed8df52c075bc4ac33ebd05`. When `n <= 2^21`, each adjacency entry stores a 21-bit node ID and an 11-bit weight; codes 0 through 2046 are inline and code 2047 refers to a per-adjacency-position u32 weight table. Larger node counts use the original u64 adjacency. The candidate processes the input at runtime and does not assume all weights are small. Both forward and reverse directions use the same encoding. The wide table allocates one u32 per edge, although only entries for large weights are written. It has not been independently reviewed or tested on full-scale data.

Seed-1 **sample**, generated independently using `official/generators/d_traverse.py`, produced the published sample hash on all 32 randomized executions (15 pairs plus one warmup pair). Shared native ARM medians were 0.02005 s candidate vs 0.02166 s baseline and CPU 0.10387 vs 0.11264 s. Peak process RSS was 54,984,704 vs 58,769,408 bytes. Individual observations and compile flags are in `sample-report.json`. The timings are short, another quick boundary test overlapped the end of this run, and sample scaling may not predict full data. These are not x86, official scoring, or cgroup measurements.

The candidate passed the independent 80-random-graph / 16,000-query Dijkstra oracle in `../track-d-balanced-frontier/oracle.py`, the 4,096-graph / 36,864-query exhaustive Floyd-Warshall suite `../track-d-balanced-frontier/exhaustive.py`, and `boundaries.py` for both n=2^21 and n=2^21+1 with highest IDs and weights 0, 2046, 2047, 2048 and UINT32_MAX. Further independent code review, full-scale hashes, Linux x86 paired timing, holdout/collision edge cases and cgroup scoring are needed. No Mac Docker was used.
