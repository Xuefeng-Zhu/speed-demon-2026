# Track A shared-mmap parallel output (not selected)

`baseline.rs` is exact selected A SHA-256 `16ae5a2e4df27269dbcc2f7b21bb9ad1022081d84e68e5b2c3f5b122a7cb04e2`. The isolated candidate waits for all hourly output buffers, computes exact cumulative offsets, opens and sizes the regular output file, maps it shared/read-write, and copies disjoint contiguous hour ranges in scoped workers before unmapping. The mutable slice is split into nonoverlapping portions before worker creation; offsets preserve hour order. Empty output avoids a zero-length mapping. It adds a second worker phase and retains all hourly buffers until copying finishes.

A first exploratory test failed because the file was opened write-only and shared read/write mmap failed on macOS. The source was corrected to open the output file read/write before benchmarking; no uncorrected output was treated as a success. Eleven randomized warmed full-seed native shared-ARM pairs of the corrected candidate measured wall 0.049376 s versus baseline 0.044340 s and CPU 0.206205 versus 0.193298 s; max native RSS 296,927,232 versus 286,343,168 bytes. All 26 full outputs including warmups matched the published hash. This is noisy native ARM evidence, not Linux/x86, official, or cgroup evidence; `report.json` retains samples. The corrected candidate passed empty/1k/100k/100k oracle cases and 14 page-end fixtures. Its unsafe map/copy/unmap and Linux filesystem behavior have not been independently reviewed; because the local result regressed, it remains unselected. No Mac Docker was used.
