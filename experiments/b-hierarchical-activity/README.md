# B hierarchical nonzero-word tracking (unselected)

`baseline.rs` is exact selected B SHA-256 `7d371fe84ce9f0fd9d3c7e6fdf02b6b37e0f1440319c654161b990cf27bb8bf3`; `candidate.rs` SHA-256 `a6397e2b78c7feb9a7584a633d3c279ff3c6fdfc228fb25a2741c00afeb327e2`. It maintains one occupancy bit per bitmap word for each of the result and scratch bitmaps. Every sparse or cached-dense OR/AND/NOT update sets or clears the corresponding occupancy bit according to the resulting word. Bitmap and occupancy arrays are swapped together on sparse AND. At each query start and scratch reuse, only words represented by the matching prior occupancy are zeroed; final summaries enumerate occupancy bits in ascending word order. Phrase handling and dense-cache limits are unchanged. Occupancy uses `2 * ceil(ceil(ndocs/64)/64) * 8` bytes per answer worker, excluding allocator overhead. This prototype does not have a density-adaptive fallback; dense updates also maintain metadata.

An `-O -C overflow-checks=yes` ARM build passed 5,364 Boolean expressions over all 64 memberships via `experiments/b-boolean-clauses/algebra.py`, `boundary.py`'s 1,000 independent set-oracle queries over 8,195 documents and 63/64/4095/4096/8191/8192 boundaries, and 40 mixed reference corpora via `experiments/b-bounded-fuzz.py`. These are finite tests; no independent review, forced-cache-zero test, actual x86 AVX2 or cgroup checks were performed.

Seven randomized paired native ARM runs against `/tmp/speed-b-full` after one warmup produced all 16 correct published full-output hashes. Candidate median wall/CPU was 0.244064/1.571518 s versus baseline 0.237827/1.525791 s (+2.6% wall, +3.0% CPU). This shared-host ARM screen uses the scalar classifier and is not x86 or official scoring evidence; it does not justify promotion. Raw data and exact flags are `arm-screen.json`. No Docker ran on the Mac.

`candidate-dense-skip.rs` SHA-256 `35035be5869ad2f1d428286bd1988ac6e469ef8e69d9672472473beb5cd498d1` adds a density-gated optimization: cached-dense AND/NOT visit only currently active words when less than half of result words are occupied; dense states use the original all-word traversal with occupancy updates. OR always visits all words of a cached dense operand. `make-test.py` can make test-only branch tracing or zero-cache builds. The traced debug/overflow build passed 5,364×64 algebra and the 1,000-query/8,195-doc independent boundary oracle, which confirmed `SPARSE_DENSE_BRANCH_REACHED`. The zero-cache debug/overflow build passed the same boundary oracle plus 40 mixed-reference corpora. These tests do not establish x86 SIMD or all-input correctness.

Seven additional randomized native ARM full-seed pairs produced all 16 correct hashes: dense-skip median wall 0.254103 s versus baseline 0.255239 s (0.45% faster), but CPU 1.535797 versus 1.509595 s (1.7% higher). Paired wall is effectively tied on this shared system; no target win is established, no density threshold tuning is justified by this screen, and the second variant is also unselected. Results are `arm-dense-skip.json`.
