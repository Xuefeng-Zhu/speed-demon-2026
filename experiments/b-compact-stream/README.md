# Track B compact Boolean posting stream (experimental, not selected)

Against the exact restored baseline SHA-256 `322cc95ee08cf6d4abc5e1b52240753f66c7eaf89ab669cb6d72b0a8487dc458`, the candidate independently remaps only Boolean-query term IDs to dense IDs. The per-chunk document-separated intermediate stream uses `u16` values when there are at most 65,535 Boolean terms (largest ID 65,534 and `u16::MAX` sentinel), and uses a separate `u32` instantiation above that count. Phrase tokens and anchor matches retain original term IDs. Term-role/Boolean-rank codes are derived from the actual queries, and no input data or answers are cached. The existing bitmap payload cap, exact word equality and strict left-to-right Boolean evaluation remain. This is an unselected experiment and has not had independent design review or real Linux AVX2 execution.

Two randomized shared native ARM batches after warmup gave candidate/baseline median wall 0.347774/0.355026 s (11 pairs) and 0.384672/0.371827 s (15 pairs); CPU 1.593636/1.580327 and 1.604684/1.598098 s. Median native process RSS was about 468.6 vs 522 MB in both batches (~10.2% lower), but mapped input and shared-host scheduling affect those figures. All 56 full hashes including warmups matched. These timings are noisy native scalar-fallback measurements, not x86 or official cgroup scores; there is no stable wall-speed win. Raw runs are in `report.json` and `repeat.json`.

The candidate passed 40 mixed reference corpora, distributed top-ten/overlapping and duplicate phrase checks, >1 MiB lines, 250,000-document/19,000-duplicate-phrase stress, and 3,072 token-alignment documents. `threshold.py` passed official-reference checks for 0, 1, 65,534, 65,535, 65,536 and 65,537 distinct Boolean terms; test-only trace confirmed 16-bit mode through 65,535 and 32-bit mode above. The latter case includes valid phrase/Boolean overlap. No Mac Docker was used. The `assert` guarding a term count beyond 2^31 is outside the official 50k-query and 8 GB limits; extreme nonofficial inputs are not claimed.

x86-64-v3, protected-page, collision/fallback and cgroup memory remain unverified. Compare the exact candidate and baseline on the target and retain the original if wall-time gains are absent under the user's speed-first priority.
