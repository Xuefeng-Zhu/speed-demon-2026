# B length-aware hash experiment

Relative to selected 15c6be0, this candidate hashes only the occupied 8-byte words of each 1–32-byte legal token, preserving zero-padded 32-byte full-key comparisons, nonlinear mixing and bounded phrase summaries. The modified source is `main.cpp`; exact baseline source is in the x86 transfer archive. Six randomized measured full-data pairs on a shared ARM Mac after warmup all matched the published hash, with median wall 1.033 s candidate versus 1.110 s selected, and median CPU 4.161 versus 4.519 s. The raw data is `mac-arm-report.json`. These measurements are noisy, native and non-official, not a target score.

The candidate passed 40 mixed reference corpora, >1 MiB read boundaries, forced-constant-hash ASan/UBSan comparisons on all lengths 1–32, and an independent ASan/UBSan dictionary property test of 250,000 distinct keys and 250,000 queries. The prior 50k adversarial collision-family fixture matched outputs and caused no comparable slowdown on a single ARM run. Deterministic hashing cannot guarantee resistance to all adversarial collision sets. Independent review found no correctness defect under the published generated-token bounds.

A further 6/9/12/16-worker screen matched all full hashes but was dominated by very high host contention; raw `workers-mac-arm-report.json` should not be used to choose a worker count. No variant is selected until x86 comparisons. The portable x86 archive contains baseline, length candidate, 9/12/16 worker variants, the comparator, official reference and tests; Library ID `libfile_5aa1841da47c8191ac0cd39e5bf695eb`, SHA-256 `cd4e50cac6481cc69082a4ac8ced5ca5c5de613c7d794e2d0cf17e7b38366910`.

A direct file-mapping experiment `mmap.cpp`, layered on the length-aware hash, avoids copying input buffers after the offsets scan. Five shared-ARM pairs after warmup had median 0.916 s mapped versus 0.934 s streaming, CPU 3.875 versus 4.051 s; process RSS 415,825,920 versus 275,136,512 bytes. All 12 full-data hashes, 40 reference corpora, large read-boundary cases, shard ordering and duplicate-phrase stress passed. `mmap-mac-arm-report.json` records every measurement. These results are noisy, non-official and too close to justify replacing streaming without x86 testing. File mappings can also fault if backing data is truncated or suffers I/O errors.
