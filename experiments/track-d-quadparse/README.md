# Track D four-digit graph-field parser (not selected)

`baseline.rs` is the exact selected Track D source. `meeting.rs` changes only the edge parser: decimal fields are consumed four digits at a time when a guarded 4-byte window has four ASCII digit high nibbles, with scalar completion. The official graph grammar guarantees unsigned decimal digits separated by exactly space or LF; no input data or precomputed results are used. No selected file changed.

Candidate passed 80 independent directed graph cases / 16,000 Dijkstra queries, 4,096 exhaustive three-node cases / 36,864 all-pairs Floyd–Warshall queries, a full-size maximum-weight chain, and 6,000 repeated/unreachable queries. `property.py` extracted the exact parser and tested 200,023 decimal values, each with five suffixes including EOF and delimiters, and one concatenated stream, with Rust overflow checks enabled. All 44 full-seed warmup/measured output hashes in two paired timing batches matched.

On a shared native macOS ARM host, 9-pair median wall candidate 0.33832 s vs baseline 0.34725 s, CPU 1.8803 vs 1.9160 s; 11-pair repeat 0.55088 vs 0.56418 s, CPU 1.8424 vs 1.8624 s. Host contention was substantial and a short property test overlapped the repeat. Raw measurements are in `report.json` and `repeat.json`. These do not establish a reliable speed gain, x86 performance or official score. The candidate remains unselected. Use `python3 experiments/track-d-quadparse/compare.py --data /path/to/full-d --build-dir /tmp/d-quad-build --report /tmp/d-quad.json --runs 11` and `python3 experiments/track-d-quadparse/property.py` for reproduction. No Mac Docker used.
