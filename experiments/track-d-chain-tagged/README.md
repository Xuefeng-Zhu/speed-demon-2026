# Tagged presence bits in chain link table (experimental, not selected)

This variant of `../track-d-chain-safe-joint/` packs four directed-presence flags into the high four bits of the first neighbor ID, reducing the per-node `Link` size from 28 to 24 bytes. The official full node ID bound (<2^21) leaves those bits unused. Non-link entries retain `u32::MAX`; weights and direction handling remain exact. Baseline in `baseline.rs` is positioned-read D at b4f634b. The tagged representation has not received independent review.

Exact-source shortcut tests passed boundary/fallback cases, 16,384 mostly-unpinned exhaustive four-node chain/multiedge cases, 1,200 random mostly-unpinned graphs at 1/2/7 workers, and 1,024 reachable chains at 1/2/7 workers. All full seed-1 hashes matched. Nine shared ARM native pairs (`report.json`) gave 0.28324 s vs original D 0.29371 s, CPU 1.72126 vs 1.84258 s. A direct 11-pair comparison against the untagged chain candidate is in `../track-d-chain-tagged-pair/report.json`: tagged 0.28058 s vs untagged 0.28147 s, CPU 1.72099 vs 1.72914 s, maximum native RSS 547,291,136 vs 555,024,384 B. The speed difference is effectively tied; these are not x86 or official cgroup results. No selected code changed and no Mac Docker was used.
