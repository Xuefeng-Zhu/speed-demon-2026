# C fixed-fraction numeric scanner on dynamic partitions (unselected)

`baseline.rs` is the exact selected dynamic-partition source SHA-256 `bcd4d7715bffd8a3dc062cad6e7aa0886a96d659fcc9170735c4d4d123f67eae`. `candidate.rs` SHA-256 `fc65f9769f2a4754863a7451bad04d49081f8423d5fb7116b3745071e06c0183` changes only `number`, rebasing the fixed-two-fraction scalar scanner from `experiments/c-numeric-cache/numeric.rs`. The format relies on official sections 2.2–2.3: valid integer fields and money amounts have delimiters, and monetary fractions contain exactly two digits. It is not an unrestricted CSV number parser. No selected source is changed.

Two randomized 15-pair native ARM full-public-seed batches after warmups matched all 64 published output hashes. Candidate/baseline median wall was `0.069848/0.070217` and `0.070618/0.068334` seconds; median CPU was `0.436707/0.426278` and `0.432378/0.424982` seconds. Parent ran a brief compile between the two batches, not during either batch. Process RSS and individual measurements are in `arm-a.json` and `arm-b.json`. The wall difference is tied then 3.3% slower, with CPU worse both times; no substantial win is demonstrated. These are shared native ARM observations, not x86, official or cgroup results. The candidate remains unselected.

The identical numeric function was previously tested in `experiments/c-numeric-cache/numeric-property.rs` over all supported cent values and several integer delimiters; that historical test does not establish complete end-to-end correctness of this new rebase. No alternate-reference, protected-page, actual x86 or official testing was performed for this candidate because the full-data speed screen was not promising. No Mac Docker was used.

Compile both sources with `rustc --edition=2021 -O -C lto=fat -C codegen-units=1 -C panic=abort`, then run `python3 experiments/c-fixed-numeric-current/compare.py --baseline <base> --variant <candidate> --data <independently-generated-full-seed-1> --runs 15 --report <new-report>` in a serialized environment. The comparator verifies the public output hash and records process RSS, which is not cgroup memory.
