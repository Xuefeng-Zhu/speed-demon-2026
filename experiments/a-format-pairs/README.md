# Track A decimal-pair formatter screen

`baseline.rs` is the exact current A source SHA-256 `9aa7eb44c30fbfc5b701ff9467d26b0a27e765520c5e766ef90d0ea6b04d85fc`; `candidate.rs` SHA-256 `b257ae7aaf3c38a2d0f84c8ab31ccdd38bf675222238d9575e42ebd0564655b3` replaces only decimal output conversion with two-digit lookup and division by 100. It remains unselected. It preserves a leading separator and handles the full u64 range. An independent overflow-check-enabled property harness (`numeric-property.rs`) passed 1 million consecutive values, 2 million pseudorandom u64 values, decimal power boundaries, u64 max and concatenated fields. A temporary Mac-only build changed Linux MAP_ANON 0x20 to Darwin 0x1000 and passed 0/1k/100k/100k synthetic oracle cases, 14 page-edge cases, and the 132,624-group latency grid at 1/2/6/12/64 workers.

All full seed-1 outputs in three randomized shared-Mac native screens matched the published hash. Eight measured pairs at 12 workers initially gave candidate/baseline median 0.05542/0.05736 s. Sixteen measured pairs at 6 gave 0.05431/0.05631 s; a sixteen-pair 12-worker repeat gave 0.04786/0.04771 s. CPU was essentially tied. These small, noisy differences do not establish a target-machine gain; the 12-worker repeat is effectively tied. Raw JSON includes warmup samples. `compare.py --data /path/to/full-a --report /tmp/format-report.json --threads 12 --runs 9` compiles Linux sources offline with x86-64-v3 on x86, randomizes order and verifies every full hash. Native RSS is not cgroup memory. For the formatter property check, run `rustc --edition 2021 -O -C overflow-checks=yes numeric-property.rs -o /tmp/numeric-property && /tmp/numeric-property`.

`profile.rs` contains only timing instrumentation around parsing, global merge and summarize/write; `profile-mac-arm.txt` reports cumulative native samples. Warm runs indicate parsing dominates (~27–35 ms), merging ~0.5–2 ms and summary/write ~7–11 ms on this Mac; the first cold run took 427 ms. Instrumentation is not a scored benchmark and does not predict the scoring box.

`hotcache-unselected.rs` is a different isolated per-worker 4096-slot endpoint cache. It verifies full endpoint bytes and falls back to the original table, so all 20 full hashes passed, but eight measured shared-Mac pairs were slower: 0.24275 s candidate vs 0.12888 s baseline, CPU 0.27947 vs 0.24953 s. Other processes were active; this negative screen is not an x86 score and the idea was not promoted. See `hotcache-mac-arm.json`. No Mac Docker was used.
