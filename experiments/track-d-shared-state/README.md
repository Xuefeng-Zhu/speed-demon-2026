# D narrow/wide shared state (unselected)

`baseline.rs` is the fixed-pool hybrid candidate SHA-256 `671c639be3400209e83e080dfb54947affd30ca71dc34ec17804d24d70292d9c`; `packed.rs` is the selected packed-u64 source SHA-256 `793d13729fe4dabe2a1ed272fef78e19567456676ed8df52c075bc4ac33ebd05`. The isolated `candidate.rs` SHA-256 `44513bbf5201b2d47986ab947ff793a35ff7e430b49ea1e6dc0453e9211241c9` does not change either queue or the cutoff decision. It allocates a single zeroed `Vec<u64>` with `2*n` elements and a single preallocated touched vector. During narrow searches the first `n` words each contain two complemented u32 distances in their low and high halves. After narrow cleanup these vectors move, using safe ownership transfer, into a wide indexed search on fallback; after its cleanup they move back. No unsafe casts or concurrent aliases are introduced. The wide indexed links are still lazily allocated and retained. Independent static review found no concrete defect in the integer packing, transfers, cleanup or phase invariants; it is not an all-input or concurrency proof.

At n=1,740,512 with 12 workers all having allocated wide fallback, the requested distance, touched and indexed-link payload decreases by 12*n*12 = 250,633,728 bytes: shared 777,067,008 bytes versus retained-state hybrid 1,027,700,736 bytes including both 65,536-entry narrow pools per worker. In a no-fallback worker, the requested zeroed distance vector grows from 8*n to 16*n bytes; allocator initialization, virtual reservation and OS page commitment can affect performance and RSS. These are requested payload figures only. Loader peaks, allocator retention and over-allocation, file cache, kernel, stacks and harness charges remain outside this accounting; **there is no proof of an 8 GiB parent-cgroup maximum**.

`python3 experiments/track-d-shared-state/verify.py --extremes` verified the candidate's fixed SHA and passed debug/overflow-checked builds with pool capacities 0, 1, 2 and 65,536. The dedicated transition test alternates self, narrow, unreachable and cutoff queries across forced capacities and checks every one of the `2*n` shared words, touched vector, fast heap and retained wide indexed heaps after each query. Capacity zero guarantees fallback for every non-self query; the test does not instrument the number of actual pool-exhaustion events for capacities 1 and 2. The four builds also passed 16,000 independent random graph answers each, 36,864 exhaustive graph answers each, cutoff−1/cutoff/cutoff+1/zero/self/unreachable checks; cap 1 and default passed n=2^21 and n=2^21+1 packed-graph boundaries, a full-size maximum-weight chain and 6,000 repeated/unreachable queries. Existing FastHeap mechanics are unchanged. The independent review did not measure actual x86 execution, RSS, cgroup peak or adversarial schedules.

Serialized native macOS ARM experiments used existing datasets; no new full dataset was generated. Each benchmark ran in randomized three-way order with one warmup, compiled optimized sources, and compared every output with the relevant expected SHA. Two 15-pair official seed-1 *sample* batches had candidate/baseline median wall times `0.020141/0.019759` and `0.019725/0.019867` seconds; maximum native process RSS was `48,742,400/44,662,784` and `48,807,936/45,121,536` bytes. One 7-pair official full seed-1 batch had candidate/baseline median wall `0.250781/0.252114` seconds, CPU `1.826345/1.822145` seconds and max process RSS `611,287,040/585,351,168` bytes. Packed source in that full batch was 0.241069 seconds and 531,808,256 bytes. A separate 7-pair synthetic sample with 2,000 repeated fallback queries (outside the official query distribution) had candidate/baseline median wall `0.008598/0.009006` seconds and max process RSS `54,755,328/55,197,696` bytes. All 144 outputs across the two sample batches and two 7-pair batches matched their expected hashes. Reports, source hashes, compiler flags and every measurement are in `sample-arm*.json`, `full-arm.json`, and `fallback-arm.json`.

These short, unpinned shared-host runs show no reliable wall gain or full-seed RSS benefit; x86 and target results are unmeasured. The synthetic fallback test does not maximize full-sized states and is not a worst-case bound. The candidate remains unselected. For target evaluation, preserve the source SHAs, use `verify.py --cpu x86-64-v3 --extremes` on an eligible Linux x86 machine, then run `compare.py` on independently generated data with the output hash verified and parent-cgroup measurement only where that interface is actually available. No Mac Docker was used.
