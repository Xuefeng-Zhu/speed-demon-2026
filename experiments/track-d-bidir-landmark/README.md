# Bidirectional directed-landmark A* (experimental, not selected)

This isolated candidate starts from the selected hugepage-hint D source at bc902c7, computes one forward landmark Dijkstra at runtime, and uses balanced directed landmark potentials in both search directions. It falls back to baseline Dijkstra when either endpoint is unreachable from the landmark. For a landmark-unreachable intermediate node it assigns a finite bound from the largest finite landmark distance. Its transformed queue keys, bound arithmetic and directed unreachable handling have not received independent review. The computation is performed from runtime input and preprocessing is counted; nothing is precomputed from contest data.

Overflow-check-enabled candidate passed 16,000 independent random graph queries, all 36,864 all-pairs queries over 4,096 three-node graphs, the maximum-size maximum-weight chain, and 6,000 repeated/unreachable queries. Every full seed-1 execution matched its published hash. Five randomized shared ARM native pairs, including all preprocessing, gave median wall 0.5381 s candidate vs 0.2698 s baseline, CPU 2.981 vs 1.842 s, and peak native process RSS 550,617,088 vs 534,544,384 B (`report.json`). The candidate is about twice as slow on this screen and is not selected; native ARM is not target x86 or cgroup evidence. No Mac Docker was used.
