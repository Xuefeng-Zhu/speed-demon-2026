# A SSSE3 latency decoder rebase (unselected)

This is an x86-only, **unmeasured hypothesis**, not a claimed speedup. `baseline.rs` is the exact current selected source SHA-256 `4af40353f517f566217b0f882ec25d8002f61d211dcc479c53f8a1dd5de7ed88`; `candidate.rs` is SHA-256 `1c794d341d052a3eaa53f9bf78360d1f628abeb096df9f5144dcd631ee6f1830`. The previous experimental implementation `../a-ssse3-latency/` was based on older source; its `parse_latency` was verified byte-for-byte identical to the current function before a mechanical replacement. Only that function changes. No input-derived answers or precomputed data are included.

For latency strings of 1–7 digits, the `target_arch=x86_64` and compile-time `ssse3` path converts decimal bytes using `PMADDUBSW` and `PMADDWD`; the fallback matches the selected SWAR code and ≥8 digits use the existing scalar loop. Loads and mapped padding are unchanged. Input digits are unsigned decimal and at most u32, as in the official spec. Static analysis of the previous identical helper found that its intermediate signed SIMD lanes do not saturate for these digits. This does not prove actual x86 code generation or performance for the rebased full program.

On macOS ARM, `python3 experiments/a-ssse3-current/property.py` compiled the exact candidate helper **without executing the x86 path** and passed 11,000,216 normal/random/guard checks. The independently overflow-checked `vector-model.rs` passed 10,000,000 semantic cases. Release arithmetic of the original baseline intentionally wraps; the extracted `property.py` compiles with `overflow-checks=no` to match the production build. The selected Track A source and remote were not changed. No Mac Docker was run.

For a Linux x86-64-v3 VM, verify the CPU has the necessary target features before compiling or running a v3 binary. Start with `python3 experiments/a-ssse3-current/property.py --require-x86` to exercise actual SSSE3 with guarded page boundaries and all 0..9,999,999 values plus random u32 tests. Then run `python3 experiments/a-ssse3-current/compare.py --data /path/to/full-a --report /tmp/a-ssse3-current-pairs.json --runs 15 --threads 12`; the comparator builds both exact sources with identical optimized flags, warms and randomizes order, verifies the official full-output SHA-256 after every run and records native wall/CPU/RSS. Re-run official-reference synthetic, page-end, forced-hash-collision and all-escape cases on actual x86 before any promotion. Native process RSS is not official cgroup peak.

Old dual-lane A is currently under a separate dot VM investigation. This SSSE3 candidate is based on **single-lane selected** `4af40353`, and must be rebased and revalidated if the selected source changes. Prior dot VM SIMD endpoint work and ARM timings do not establish SSSE3 latency-decoder benefit. Target x86, cgroup, source-size and official board results are all outstanding.
