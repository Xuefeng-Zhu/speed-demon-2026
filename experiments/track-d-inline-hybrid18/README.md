# Four-inline-edge CSR on the selected bounded hybrid (unselected)

The exact selected batch16 hybrid baseline is `baseline.rs`, SHA-256 `7fd333be25133a78264cb4b84441de46d4c8bcbfd73914af23761f23d8c47f17`. The isolated candidate `candidate.rs`, SHA-256 `aa155e6c4866795b548cf1a327d5379b69b1bc35437ce1c8dc37c3e3c0a71d61`, replaces its CSR with the earlier `../track-d-inline-compact/meeting.rs` four-inline layout. Each node row contains up to four full `(weight,node)` u64 edges and a contiguous overflow range. It uses full-width edges for all n and weights; both narrow search and exact indexed-wide fallback use the same row iterator. The parser, query scheduler, capped queue, 16-entry batching, distance cutoff and fallback remain as in the exact baseline. For the official maximum m=5,000,000, `(overflow << 3) | min(degree,4)` fits u32. No selected source was changed.

An independent exact-layout test from `../track-d-inline-compact/independent-review.py` passed 720 n/worker/edge-count configurations and four high-skew/duplicate configurations (including weights zero and u32::MAX). Candidate passed 80 random directed graphs / 16,000 independent oracle queries, all 4,096 three-node graphs / 36,864 all-pairs queries, four additional skew/high-degree cases, cutoff-1/cutoff/cutoff+1/unreachable/zero/self cases, and n=2^21 and 2^21+1 boundary fixtures. Variants with pool caps 0, 1 and 2 each passed the 16,000-query oracle and cutoff suite. These are finite native tests, not hidden-data or cgroup proof. No full-size chain/repeated-query suite or independent review of the combined current hybrid source has yet been run.

On the shared native macOS ARM host with one warmup and 15 randomized full-seed pairs, every one of 32 outputs matched the published hash. Candidate median wall **0.277460 s** vs baseline **0.258296 s** (7.4% slower); candidate median CPU **1.733193 s** vs **1.781356 s** (2.7% lower); max native process RSS **676,134,912** vs **587,186,176** bytes. Candidate had lower wall in 3/15 measured pairs. `full-arm.json` contains individual observations, flags and source hashes. Process RSS is not parent-cgroup memory; shared-host native ARM results are neither target x86 nor official scores. A prior sample-screen attempt was interrupted during compilation after another agent reported simultaneous generator work; it produced no timing report. No Mac Docker was used.

Given the slower observed wall and higher process RSS, this candidate remains unselected; no target or x86 speedup is established. Exact layout can change sensitivity to ISA, caches and node degree, so the result is not a universal performance proof. To reproduce, provide independently generated full seed-1 data and run `python3 experiments/track-d-inline-hybrid18/compare.py --data /path/to/full --build-dir /tmp/d-inline18-build --report /tmp/d-inline18-report.json --runs 15`; it checks the published output hash. Use `python3 experiments/track-d-inline-compact/independent-review.py experiments/track-d-inline-hybrid18/candidate.rs` for the layout test and the graph oracle suites in `../track-d-balanced-frontier/` for further verification.
