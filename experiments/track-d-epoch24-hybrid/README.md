# D epoch-tagged 24-bit narrow distances (unselected prototype)

`baseline.rs` is the exact selected capped hybrid (`671c639be3400209e83e080dfb54947affd30ca71dc34ec17804d24d70292d9c`). This isolated candidate stores a 16-bit query epoch and two complemented 24-bit distances in one `u64` per vertex, removing the narrow search's touched list. A word whose epoch does not match is logically unreached; on a new visit it is initialized for the current epoch. Epoch wrap clears the whole word array before epoch 1 is reused. Fast queues, caps and exact wide search are unchanged.

The runtime cutoff is `2^24 - 1` (the all-ones unreached sentinel). A relaxation at or above that threshold is recorded as discarded. If a narrow answer is below the cutoff, nonnegative weights ensure any shorter path has both its prefixes and suffixes below the cutoff. Otherwise, when any relaxation was discarded, the existing exact u64 search reruns the query from scratch. A query without discarded relaxations follows the original stopping rule and can return its narrow result. Pool exhaustion always forces an exact rerun. These are proof notes, not independent review or an all-input proof.

The candidate is unselected. An independent static review found no concrete defect in epoch packing, cutoff, lookup, wrap or wide-fallback conditions. `run-property.py` built temporary source variants with pool capacities 0, 1, 2 and 65,536 under optimization, overflow checks and debug assertions. Each passed 38,400 seeded graph-query answers against an independent Dijkstra oracle (153,600 total), plus explicit cutoff−1/cutoff/cutoff+1/u32-maximum, self/unreachable, repeated state reuse, stale epoch-1 slots and the `0xffff` to 1 wrap. Heap cleanup was checked after every query. This is finite native ARM evidence, not an all-input proof.

One randomized 15-pair full-seed native ARM screen after warmup produced the published output hash in all 32 runs. Median wall was 0.273640 s candidate versus 0.268018 s baseline; median CPU was 1.814285 versus 1.821762 s and maximum process RSS 632,766,464 versus 613,335,040 bytes. This single shared-host batch shows no compelling speed or observed RSS improvement; raw observations, source hashes and compiler flags are in `arm-a.json`. It is not an x86 or official timing or a parent-cgroup measurement. Cgroup worst-case must include the separately retained wide fallback state, allocator, page cache and loader. No Docker was used on the Mac.

Reproduce with a free native CPU window and independently generated full data: `python3 experiments/track-d-epoch24-hybrid/compare.py --data /path/to/full-d --build-dir /tmp/sd-epoch24-build --report /tmp/sd-epoch24.json --runs 15 --seed 8473`. The scripts do not ship input data or answers beyond the published output hash.
