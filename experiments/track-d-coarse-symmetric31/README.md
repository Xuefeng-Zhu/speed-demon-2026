# Symmetric coarse-queue pruning — unselected

`baseline.rs` is the selected forward-pruned source SHA-256 `c33d3984871fb22ed7c2d678b3a3562ac82d46cb952a8a0461980301c5a553ef`; `candidate.rs` SHA-256 `db6222ca195561bf39795986206f21298b9eb08fd071e3fb3f19bf8bb31d80aa`. The isolated trial applies the same opposite-bucket-bound test and mandatory meeting update to both directions; it leaves exact wide fallback and pool caps unchanged. Unlike selected forward-only pruning, neither direction is guaranteed unpruned, so a surviving-optimal-path-frontier invariant is required. An independent review found no concrete counterexample, but only a proof sketch: simultaneous pruning, coarse re-expansions, equality, zero cycles, cutoff and empty-queue termination would require stronger review before consideration. No all-input correctness or hidden-input cgroup bound is claimed.

`verify.py` passed seven forced capacities 0/1/2/15/16/17/65536, 16,000 random and 36,864 exhaustive directed graph answers per capacity, threshold, 2^21 packed/wide boundaries, maximum-weight chain and repeated/unreachable queries. `adversarial.py` passed ten dense zero/parallel directed graphs with 23,040 all-pairs queries per cap (2/16/65536), exercising 175,764 repeat expansions and 80,519 inverted exact-key pops at default capacity. `long_bucket.py` passed the 8,191-node same-bucket zero-cycle and actual forced cap-2/16 exhaustion with exact fallback. Finite tests are not a proof.

In a coordinated warm-cache shared ARM screen, nine randomized full-seed pairs measured candidate median wall **0.252921 s** versus baseline **0.225861 s** (about 12.0% slower), median CPU 1.782163 vs 1.573448 s (13.3% higher). All 20 timed/warmup outputs matched published full-seed hash. Native process RSS and ARM times are not x86 target or parent-cgroup measurements. Raw observations, flags and source hashes are in `arm-screen.json`. This result does not justify an x86 package or promotion. No Docker was run on the Mac.
