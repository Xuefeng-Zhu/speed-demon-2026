# Capped directed degree-two shortcuts (prototype, not selected)

The baseline is exact restored Track D at `451429c` (SHA-256 `1022f4d9c9956b17fd054e96a26d09551eff61936a851edf88505e12e2b1946c`). The candidate computes runtime undirected distinct-neighbor counts, preserves every query endpoint, and substitutes core-to-core shortcuts across degree-two non-query nodes in each directed CSR. Original intermediate rows are retained. A missing directed arc, total weight above `u32::MAX`, or more than 16 steps leaves the original core edge intact. Self-loops and repeated edges are retained. Preprocessing is timed and based only on runtime input.

This is an exploratory prototype, **not independently reviewed or selected**. An overflow-checked build passed 16,000 random directed graph queries, 36,864 exhaustive three-node queries, a maximum-size maximum-weight chain, and 6,000 repeated/unreachable queries. `chain_stress.py` passed 376 further chain/cycle cases with zero/max weights, duplicates, self-loops, directed gaps and optional pinned intermediate query endpoints. All 12 full seed-1 executions (five measured pairs and warmups) matched the published output hash.

On the shared ARM Mac, five randomized native paired runs including preprocessing gave median 0.28910 s candidate vs 0.28275 s baseline, CPU 1.84231 vs 1.86056 s, and maximum native process RSS 559,382,528 vs 534,986,752 B. The screen shows no speed win and is not x86, official scoring, or cgroup evidence. Raw samples are in `report.json`. Before any selection, the transformed-graph equivalence requires independent review, tests for directed one-way chains, cycles, duplicate edges, pinned intermediates, 16-step and 32-bit-overflow fallbacks, and repeat target performance under official limits. No Mac Docker was used.
