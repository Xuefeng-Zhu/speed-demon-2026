# D hybrid cached radix bucket minima (unselected)

`baseline.rs` is the exact selected bounded hybrid (SHA-256 `671c639be3400209e83e080dfb54947affd30ca71dc34ec17804d24d70292d9c`). `candidate.rs` (SHA-256 `628b0922b43babe854af632876ce43a328c3d5b82286157aa6d7b1bf5b8c81ef`) caches each FastHeap bucket's minimum on insertion and redistribution. When the minimum bucket is materialized it uses the cached value and avoids the original linked-list minimum scan. Bucket-zero pop resets the cached minimum when its list becomes empty; clear resets all minima. Pool capacity, cutoff behavior, exact indexed wide fallback and graph loading remain unchanged.

This reimplements `track-d-bucket-mincache/`'s idea on the selected fixed linked-node FastHeap; the prior experiment used an older vector-backed heap and was slower. Independent static review found no concrete minimum invariant, equal-key, failed-insertion, redistribution or reset defect. `python3 experiments/track-d-hybrid-bucket-min/verify.py` passed on ARM with debug assertions and overflow checks: forced pool caps 0/1/2/default, one million multiset-model heap operations, 60,000 extra equal-key/mixed-bucket/clear operations auditing cached minima, actual 65,536-node pool fill/failure/refill/drain across five cycles, 16,000 randomized and 36,864 exhaustive graph queries per cap, threshold transitions and the 2^21 node/weight boundaries. These finite tests do not prove correctness for every graph or concurrency schedule.

One serialized randomized 15-pair full public seed-1 native ARM run (one warmup pair; input files independently hash-verified) matched the published output hash in all 32 executions. Median wall was **0.281116 s candidate vs 0.252550 s baseline** (~11.3% slower), and median CPU was **2.005511 s vs 1.811169 s** (~10.7% higher). Max native process RSS was 585,449,472 vs 611,565,568 bytes; native peak RSS is not official parent-cgroup memory and is scheduling-sensitive. Exact run records and compiler flags are in `arm-a.json`. This negative screen is consistent with the additional minimum maintenance on each successful push and redistribution; it is not proof of target x86 behavior. No Mac Docker was used.

An independently instrumented current-hybrid full-seed profile counted about 1.82M redistributions and 32.52M node visits each in the original minimum scan and redistribution, but instrumentation perturbs performance. Despite that work, the candidate lost in the actual uninstrumented native screen and remains unselected; no x86 or official board run is recommended without new evidence.

To reproduce the full ARM comparison, compile and benchmark both sources with identical release flags using `python3 experiments/track-d-hybrid-bucket-min/compare.py --data /path/to/full-d --build-dir /tmp/sd-d-min-build --report /tmp/sd-d-min.json --runs 15 --seed 8681`; use a separate serialized machine and target `x86-64-v3` as appropriate. The script verifies every published output hash. It does not measure cgroup peak or hidden data.
