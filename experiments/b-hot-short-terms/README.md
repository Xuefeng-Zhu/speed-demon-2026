# B sample-selected hot short terms (not selected)

This experiment chooses the two or four most frequent short query terms from the same input sample already read for phrase anchoring. It compares the exact packed key against these terms before falling back to the existing exact short-key hash. Sampling affects the fast path only, not the answer. Phrase summaries and bitmap limits are unchanged. This differs from `b-tiny-direct` (fixed short-token direct table) and `b-short-cache` (per-worker direct-mapped cache).

Seven randomized native shared-Mac ARM pairs after one warmup per implementation all matched the published full seed-1 output hash. For two hot terms median wall was 0.259748 s versus 0.262028 s baseline; median CPU was 1.603959 versus 1.571910 s. Four terms took 0.289547 versus 0.275158 s wall and 1.688400 versus 1.589647 s CPU. The small two-term wall difference and increased CPU, and the four-term regression, do not support promotion on this noisy screen. These timings exercise scalar ARM, not the scoring target's AVX2; native process RSS is not cgroup memory. Full reference or adversarial tests were not run for these unselected candidates.
