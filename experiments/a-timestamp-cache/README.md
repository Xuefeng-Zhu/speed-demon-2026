# A timestamp load and endpoint-cache screens (not selected)

The source files are isolated variants of selected Track A (`baseline.rs`, SHA-256 `9aa7eb44c30fbfc5b701ff9467d26b0a27e765520c5e766ef90d0ea6b04d85fc`). `timestamp.rs` obtains timestamp digits from one unaligned eight-byte load instead of separate byte accesses. `cache.rs` uses a 1024-entry per-parser direct endpoint-ID hint keyed from the first input word; every hit checks the entire endpoint byte-for-byte and requires its following space, and every miss falls back to the original table. `combo.rs` combines both changes. They have not been selected or independently reviewed for all legal inputs.

On macOS ARM, temporary copies changed only the Linux MAP_ANONYMOUS flag 0x20 to Darwin 0x1000. In nine paired 12-worker full-seed measured runs after warmup, timestamp vs baseline medians were 0.05823 vs 0.06066 s (CPU 0.2073 vs 0.2118 s); cache vs baseline medians 0.05366 vs 0.05634 s (CPU 0.2165 vs 0.2140 s). In a separate randomized four-way 12-run rotation, medians were baseline 0.07080 s, timestamp 0.06995 s, cache 0.06793 s and combo 0.07133 s; CPU medians 0.2305 / 0.2286 / 0.2320 / 0.2382 s respectively. Every full seed-1 output matched the published hash, including warmups. Raw runs are `timestamp-screen.json`, `cache-screen.json` and `rotation.json`. Shared-host activity was present; small and contradictory wall changes do not establish an x86 or official speedup. Native RSS is not cgroup memory.

For reproduction copy a variant to `candidate.rs` alongside `baseline.rs` and run `python3 compare.py --data /path/to/full-a --report /tmp/a-pair.json`. Both sources use Linux's mmap flag and the driver compiles offline and verifies every full hash. Before considering promotion, test fresh references, page boundaries, all endpoint lengths, table growth, forced collisions and target x86; the cache is a hint only, but its correctness and memory-bound behavior have not had independent review. No Mac Docker was used.
