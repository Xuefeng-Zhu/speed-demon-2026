# Track A profiling ablations (experimental)

All variants derive from exact automatic-worker selected baseline `2146b716`, SHA-256 `9aa7eb44c30fbfc5b701ff9467d26b0a27e765520c5e766ef90d0ea6b04d85fc`. They are independent alternatives, not a combined patch. No variant is promoted.

- `reuse-linux.rs` retains per-summary-worker `start`, `errors`, `lat`, and `next` buffers between hours, resetting contents before use. Output ownership remains per-hour.
- `cache-linux.rs` saves local→global endpoint IDs while inserting the first time and maps them through sorted ranks without a second table lookup.
- `reserve-linux.rs` reserves output capacity based on 96 bytes per distinct name; capacity is merely a hint.
- `workers-linux.rs` adds optional positive `SD_SUM_THREADS` to set summary worker count independently of `SD_THREADS` parse workers; without it the original behavior is preserved.
- `no-madvise-linux.rs` removes only the per-shard `MADV_POPULATE_READ` call. Linux-only testing is necessary; the syscall constant is not applicable to macOS.

Seven randomized full seed-1 measured runs per variant after one warmup on a shared Apple ARM host, using a temporary Darwin MAP_ANONYMOUS flag adaptation, all matched the published output. Median wall s for 6 / 12 parse and summary workers: baseline .045993/.043450, reuse .046037/.043764, cache .044314/.042393, reserve .044505/.044180. `screen.json` contains all samples, CPU, RSS and faults. Seven randomized worker-matrix screens gave 12 parse / 3,6,9,12,18 summary medians .053252/.046078/.046580/.046854/.046379 seconds (`workers-screen.json`); host load and ordering make these noisy and nonofficial. Full hash for every run passed. Candidate reuse/cache/reserve also each matched the independent empty, 1k, 100k and 100k synthetic oracle suites. No Mac Docker commands were used.

Local rustfmt 1.9 nonempty non-line-comment physical lines: baseline 266; reuse 293; cache 267; reserve 266; workers 271; no-madvise 266. These are **not** official scc or pinned rustfmt 1.10 S values. Obtain authoritative static counts on the competition harness. Linux source SHA-256 hashes are in the final report generated by `compare.py`.

Independent review confirmed that the baseline is byte-identical to current A at 073646e and found no stale-state or cross-thread defect in scratch reuse. A temporary Darwin-adapted build passed `reuse-state-test.py` against the official reference on 72 alternating empty, small and large hours with workers 1, 2, 3, 7, 12 and 64. Run `python3 experiments/a-ablation/reuse-state-test.py --binary /path/to/reuse --reference official/reference/a_ingest.py` from the repository root. These checks are not x86 performance evidence.

## Offline VM comparison

The commands below use the Library archive, which includes `tests/` and `official/`. In this repository the tests are under `../../track-a-verification/` and reference under `../../official/reference/`. Use a disposable copy of full seed-1 data, Rust installed, no external packages:

```
python3 compare.py --data /path/to/disposable-full-a --threads 12 --runs 9 --report /tmp/a-ablate-warm.json
python3 compare.py --data /path/to/disposable-full-a --threads 12 --variants baseline workers --sum-threads 6 --runs 9 --report /tmp/a-summary6.json
python3 compare.py --data /path/to/disposable-full-a --threads 12 --variants baseline workers --sum-threads 18 --runs 9 --report /tmp/a-summary18.json
python3 compare.py --data /path/to/disposable-full-a --threads 12 --variants baseline no-madvise --drop-cache --runs 5 --report /tmp/a-populate-cold.json
```

The default comparison uses randomized order, one warmup each, `x86-64-v3` on x86, and verifies the official full hash after every run. Each sample captures wall, user+system CPU, `wait4` per-process max RSS and major/minor faults. `--drop-cache` calls `POSIX_FADV_DONTNEED` before each sample and uses Linux `mincore` to record resident pages immediately before execution; it may fail to evict pages held elsewhere and affects the host's cache, so use **only a disposable copy** and record observed residency. This cold screen is an ablation; the official harness prewarms input. `--generic` disables x86-v3. Native RSS is not official warmed-cgroup memory; use the official runner for definitive wall and memory.

Build each promising variant and run `tests/test.py --binary /path/to/binary --io directories`, `tests/page_end_test.py --binary /path/to/binary --reference official/reference/a_ingest.py`, and `tests/latency_grid_test.py --binary /path/to/binary` before selection. Additional seeds and independent review are needed. No datasets, credentials or binaries are included.
