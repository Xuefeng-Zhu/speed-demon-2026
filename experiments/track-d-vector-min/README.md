# ARM NEON radix-bucket minimum (experimental, not selected)

Exact restored D `451429c` is baseline. Candidate uses a fully initialized 16-byte C-layout heap item and, on AArch64 with NEON, guarded two-item deinterleaving loads plus vector comparisons to find the minimum key in a radix bucket. A scalar fallback handles other targets; no x86 SIMD version is implemented. Initialized padding avoids reading uninitialized memory in the vector load. The target competition system is x86-64, so the Mac-native NEON screen cannot establish any target gain.

The exact-source min helper passed 65,600 random/edge-case bucket comparisons with overflow checks. The whole candidate passed 16,000 independent random directed queries, 36,864 exhaustive small-graph queries, the maximum-weight full-size chain, 6,000 repeated/unreachable queries, and all full seed-1 hashes. Nine shared ARM pairs (`report.json`) showed noisy median wall 0.31825 vs 0.35742 s and CPU 1.87991 vs 1.84625 s candidate vs baseline. The 11-pair repeat (`repeat.json`) overlapped the short property-test compile/run and must be treated as contaminated; its medians 0.30840 vs 0.30507 s wall and 1.82455 vs 1.81614 s CPU do not establish a gain. Neither test is an official/x86/cgroup score. No selection or Mac Docker use occurred.
