# D radix-heap occupancy bitmap (not selected)

This experiment replaces the radix heap's scan for the next occupied bucket with a `u128` occupancy bitmap updated on push, pop, redistribution and clear. It retains the exact search algorithm. Baseline is the Track D source at commit `1b2da3d095acd09779f08205f9329f79b7ba40d7`, SHA-256 `fa01c6bbda5b7264ad104832ef284003fb7cc37f6cfc56e7fdab409abb2a9047`; the candidate `bitmap.rs` SHA-256 is `9c36ad1a98a310bd15b16a346f212b976fd02f60cb80cd12c8b2523ef5f70b21`.

Both compiled with `rustc --edition 2021 -O -C lto=fat -C codegen-units=1 -C panic=abort` and passed 80 independently generated directed graphs with 200 Dijkstra-oracle queries each, including zero and maximal u32 weights. Use `python3 experiments/track-d-heap-bitmap/oracle.py /path/to/baseline /path/to/candidate` to repeat. Both binaries then matched the published full seed-1 output hash on all ten native executions apiece; two warmup rounds are included in `mac-arm-bench.json`. Eight measured randomized-order pairs on a shared macOS ARM host gave median wall times of 0.686883 s baseline and 0.710338 s bitmap, median CPU 3.471503 and 3.570246 s, maximum per-process RSS 560,955,392 and 561,643,520 bytes. The native process RSS is not official cgroup memory; there was shared-host variability and these results do not predict x86 scoring. The bitmap was not promoted because it was slower in this screen and adds source and heap bookkeeping.
