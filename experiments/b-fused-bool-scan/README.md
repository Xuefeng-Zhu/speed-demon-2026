# B fused Boolean stream during tokenization (not selected)

The candidate emits and deduplicates Boolean term IDs during tokenization instead of checking Boolean roles in the subsequent document-token loop. It retains the full document token sequence for exact phrase checks, and retains bounded phrase summaries, bitmap cap and exact lookups. The callback context contains the stream, last-document stamps, phrase summaries and current local document ID. This is an isolated source experiment, not selected code.

Five measured randomized native shared-Mac ARM pairs after one warmup each matched the published full seed-1 SHA-256. Median wall time was 0.290975 s candidate versus 0.281276 s baseline; median CPU 1.647341 versus 1.587231 s. Every sample is in `report.json`. Other jobs may have run; ARM uses scalar fallback rather than the scoring CPU's AVX2 and process RSS is not cgroup memory. The fused candidate was slower in this screen and is not recommended on this evidence.

The candidate passed 40 mixed official-reference corpora covering ASCII/Unicode, punctuation, case, overlaps and duplicate queries, and the distributed top-ten/phrase overlap fixture. No dedicated forced-collision or sanitizer review was performed, because the performance screen was negative. To reproduce, build `baseline.rs` and `candidate.rs` with matching Rust release flags, then run `python3 experiments/b-rust-lengthhash/compare.py --baseline /path/to/baseline --candidate /path/to/candidate --data /path/to/full-b --runs 5 --report /tmp/b-fused.json`. Input must be generated independently. No Mac Docker was used.
