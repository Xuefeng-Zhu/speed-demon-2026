# Dynamic query blocks over shared global index (experimental)

This unselected candidate is a follow-up to `experiments/b-global-queries/shared.rs`, not the currently selected Track B. Baseline SHA-256 `58ea98f48a322c3af1837a1dd1a19767250232e4c3f690e298c7e9ac95c83dfe`; candidate `7d371fe84ce9f0fd9d3c7e6fdf02b6b37e0f1440319c654161b990cf27bb8bf3`. Workers claim unique 256-query ranges using an atomic counter, return `(start, results)` blocks, and the caller sorts blocks by start before formatting. Shared immutable global dense bitmaps and the total 64 MiB payload cap are unchanged. The exact original input query order is restored; no query values or results are precomputed.

On native shared-Mac ARM with the original shuffled full seed, 11 randomized warmed pairs gave candidate/baseline medians 0.245206/0.256943 s wall and 1.517083/1.524449 s CPU; 15-pair repeat 0.242444/0.242330 s and 1.532952/1.519588 s. All 56 official full output hashes including warmups passed. The order of the difference was not stable.

A separate legal synthetic query-order experiment sorts the supplied queries by type, operator count and bytes, without modifying corpus data. Against the contiguous-query candidate's output as a differential oracle, 11 randomized warmed pairs measured 0.255862/0.281156 s wall and 1.512980/1.484746 s CPU; 15-pair repeat 0.265048/0.291368 s and 1.519646/1.491125 s. Every output matched; ~9% lower wall in this skewed scenario came with ~2% higher CPU. This is not an official dataset/hash or score. `skew-benchmark.py` creates and deletes the reordered input and computes its differential hash at runtime; it contains no cached answers or datasets. All figures are shared-host native ARM scalar-tokenizer results, not Linux x86 or cgroup evidence. Raw samples appear in `report.json`, `repeat.json`, `skew.json`, and `skew-repeat.json`.

Atomic claims produce unique nonoverlapping ranges; sorting by start reconstructs query order. Output vectors are retained per block, and no document or phrase result crosses query boundaries. The inherited shared cache's `OnceLock` publication and atomic quota are unchanged. `independent-review.py` tested 323,200 exact-reference queries across 1/2/3/7/12/32 workers, zero/eight-byte caps and document counts around 64-bit boundaries. `order-boundary.py` passed reference comparisons for 0/1/2/255/256/257/511/512/513/1001 queries, with duplicates and mixed BOOL/PHRASE; 250k-document/19k-duplicate stress passed. These tests do not prove all schedules or measure target performance. No Mac Docker was used.

Run `python3 experiments/b-global-query-blocks/independent-review.py` and `python3 experiments/b-global-query-blocks/order-boundary.py --binary /path/to/candidate --reference official/reference/b_index.py`; use `experiments/b-rust-lengthhash/compare.py` for hash-checked paired official-seed testing and the skew script separately. Native RSS is not cgroup peak. After x86 validation of all three variants, this candidate is selected for a separate official practice comparison.

Independent dynamic-order review found no defect. `independent-order.py` uses a unique expected answer for every query and checks 0/1/2/255/256/257/511/512/513/767/768/769/1023/1024/1025 query counts with 1/2/7/32/64 workers. Delaying the first block and deliberately reversing intermediate block order still produced correct output; a negative-control build with sorting removed failed as expected. These are native ARM tests, not a proof of all schedules.

## Dot VM x86 comparison

The parent-run shared native x86 VM found the dynamic-block version 2.0–2.3% faster on normal full-seed pairs. On a clustered expensive-query stress it measured 0.0293 s versus 0.04675 s for contiguous shared-cache and 0.03464 s for original baseline. Across this, C fused and A lookup-order packages, 314 full hashes, 28 alternate references, sorted/skew/escape and SIMD/concurrency/collision checks passed. These native measurements do not establish an official score or cgroup peak; the candidate remains isolated pending separate official testing.
