# Track A inline endpoint slots (not selected)

The isolated candidate stores each probe slot's full hash, mapped start, endpoint length and ID inline, instead of loading the ID from the slot and then looking up its metadata in the names vector. Exact-byte equality, hash calculation, probe order and growth reinsertion order remain unchanged. The extra slot bytes increase a 4,096-slot table by approximately 80 KiB; baseline SHA-256 is `16ae5a2e4df27269dbcc2f7b21bb9ad1022081d84e68e5b2c3f5b122a7cb04e2`, and candidate is `fc2b1d79aeb178aea05a3d319afc52e0d3229cb041dc9bbbd96a9eb06c9bb016`. It is not selected.

Two randomized paired shared-macOS ARM full-seed comparisons at 12 workers after warmup measured baseline/candidate wall medians 0.043466/0.043380 s (11 pairs) and 0.061231/0.061201 s (15 pairs); CPU medians 0.194812/0.188705 s and 0.207636/0.202619 s. All 56 full executions, including warmups, matched the published output hash. CPU fell about 2.4–3.1% but wall was essentially tied; host contention and architecture mean these are not an official or x86 result. Native RSS includes mapped data and is not the cgroup peak. Test copies used Darwin MAP_ANON 0x1000 instead of Linux 0x20. Raw samples and adapted-source hashes are in `screen.json` and `repeat.json`.

Independent static review found no defect in probe wrap, hash collision handling, exact comparison, or stable IDs after rehash. Spec endpoint length is at most 125, so the slot's u32 length conversion is safe; the original table already stores IDs as u32. Candidate and test-only all-hashes-zero builds passed the 2,422-endpoint reference/growth suite at 1/2/3/7/12/32 workers. Candidate additionally passed empty/1k/100k/100k synthetic oracle cases, 14 page-edge/reference fixtures, and a 132,624-group latency grid at 1/2/6/12/64 workers. No Mac Docker was run. Target timing and official memory and correctness gates remain unmeasured; a win has not been established.
