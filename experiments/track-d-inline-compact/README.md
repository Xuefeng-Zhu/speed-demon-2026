# Compact four-inline-edge CSR (experimental, not selected)

`baseline.rs` is the balanced-frontier source before the hugepage hint, SHA-256 `1022f4d9c9956b17fd054e96a26d09551eff61936a851edf88505e12e2b1946c`. `meeting.rs` builds a row per node with up to four packed edges in the row; only further edges occupy an overflow array. It computes each layout from the runtime graph and retains edge order and direction. Each row encodes the overflow length as `len >> 3` and inline count as `len & 7`. Under the official full specification, degree is at most five million, so the encoding fits `u32`; it must not be generalized above roughly 536 million edges without changing the representation. Compared with the currently selected hugepage-hint source at `bc902c7`, **this candidate lacks the hint and must be rebased onto that exact source before any performance comparison**.

The exact-source independent reviewer found no concurrency, ownership or correctness defect under official bounds. `independent-review.py` passed 720 combinations of n/worker count/edge count (including empty graphs, workers > n, 3/4/5 degree transitions and u32-max weights) and 220,000 skewed/duplicate edges at 1/2/7/32 workers, with Rust overflow checks. The candidate passed 16,000 independent random-graph queries, 36,864 all-pairs queries on 4,096 exhaustive graphs, the maximum-size and maximum-weight chain, 6,000 repeated/unreachable queries, and the independent skew/high-degree oracle `high_degree.py` with 1/2/7/32 forced workers. Every published full seed-1 hash matched.

Nine native shared ARM measured pairs (`report.json`) had medians 0.4914 s candidate vs 0.4889 s baseline, CPU 1.788 vs 1.921 s; peak process RSS 594,640,896 vs 535,494,656 B. A later 11-pair repeat (`repeat.json`) overlapped the three-inline experiment and is contaminated; do not draw wall-time conclusions from it. A separate 11-pair repeat without our own overlapping benchmark (`repeat-clean.json`) measured 0.2714 vs 0.2698 s wall, CPU 1.720 vs 1.848 s, peak RSS 595,050,496 vs 535,134,208 B. All are shared-host ARM native results, not official scoring-box or cgroup measurements; no wall win was established. No Mac Docker was used.

Use `compare.py --data /path/to/full --build-dir /tmp/build --report /tmp/report.json` for randomized paired full-hash runs; validate with `python3 independent-review.py meeting.rs`, `python3 high_degree.py /path/to/binary`, and the independent graph-oracle suite in `experiments/track-d-balanced-frontier/`. Always compare identical runtime hints and measure official cgroup memory separately.
