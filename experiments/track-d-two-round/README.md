# Bounded two-round low-degree contraction (experimental, unselected)

This candidate applies two sequential rounds of the one-round graph transformation in `../track-d-independent-contract/` to the runtime graph before answering queries. `baseline.rs` is the exact selected positioned-read source, SHA-256 `ac9674a11b90244c63a518ee94eb7a9547353540ff564672aaa128ac4851a2ea`; `meeting.rs` candidate SHA-256 `6673a36206ac04e4154337a5ef90b774d3b35eb3b375d7bbe8430244d55eb709`. It requires independent review and is not selected. All graph and query-derived work is done during the run.

Each round pins every source and target, excludes self-loop vertices and vertices whose maximum incoming plus outgoing weight exceeds `u32::MAX`, and selects an independent subset of eligible vertices. Every incoming/outgoing pair through a removed vertex receives its exact summed-weight shortcut; nonnegative self-return walks are discarded. Because the removed set has no internal edges, every path between pinned endpoints can replace its removed-node two-edge segments by shortcuts, and every shortcut expands to a real path. Applying that argument to each round composes the distance guarantee. Multiedges are retained. This is a proof sketch, not an independent review.

Before allocating the next CSR, the code computes `m + sum(indegree(v) * outdegree(v) - indegree(v) - outdegree(v))` over removed vertices. Independence ensures each incident edge is subtracted once; omitted self-return arcs make the sum an upper bound. If it exceeds the global limit `min(2 * input_m, 5,000,000, u32::MAX)`, the round returns the prior graph unchanged. This guards output growth and 32-bit offsets on the official workload but does **not** establish a complete worst-case 8 GB process/cgroup bound. Large hidden-data, maximum-size and cgroup tests remain necessary. The original full spec has 5,000,000 edges; the two-times term allows small stress cases to exercise a growing first round. Optional `SD_CONTRACT_TRACE` reports round bounds/fallbacks on stderr.

Overflow/debug-checked builds passed the existing 80 random directed-graph Dijkstra suite (16,000 queries) and `stress.py`: 127 sparse/dense, duplicate, max-u32/zero weight, pinned-endpoint, and 3-in/3-out fixtures; one fixture batches all 4,096 three-node directed graphs with one unpinned vertex per graph. Each fixture tests the candidate and a separately compiled forced-zero-cap fallback against a Python Dijkstra oracle (254 binary comparisons). One directed chain verifies that *both* rounds contract; an opposing 3-by-3 bipartite construction verifies a **natural second-round fallback**. The tests do not prove correctness or memory safety for all valid graphs.

No speed measurement is claimed for this two-round candidate. The prior one-round candidate on shared ARM took 0.29007 s versus 0.27451 s baseline (five pairs), despite 6% lower CPU and reduced arc count. Two rounds may add more preprocessing than they save. No x86, official, full-seed, or cgroup performance has been established; no Mac Docker was used. To test, compile `meeting.rs` with debug and overflow checks, make a separate copy whose `let max_edges = ...` assignment is replaced by `let max_edges = 0usize;`, compile it with the same checks, then run `python3 stress.py /path/to/meeting /path/to/forced-zero-cap`. Run `../track-d-balanced-frontier/oracle.py /path/to/meeting` separately. Full-data paired results, independent review, targeted transformation/memory tests, and exact-head official practice are required before selection.

Independent static review found no graph-equivalence or upper-bound defect: eligible neighbors cannot both be removed, all endpoints are pinned, exact shortcut weights fit u32, and independently bounded rounds compose. The bound counts incoming/outgoing products even for self-return shortcuts that are omitted, so it remains conservative with parallel arcs. This review is not a proof of complete process-memory safety: distance arrays, radix-bucket retained capacity and allocation peaks still require cgroup measurement. No additional independent oracle run was completed as part of that review.
