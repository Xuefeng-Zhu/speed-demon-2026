# Safe in-place directed degree-two shortcuts (experimental, not selected)

Baseline is positioned-read Track D at `b4f634b`. The candidate builds an immutable per-node table for non-query vertices with exactly two distinct undirected neighbors. For each direction it retains the minimum actual directed edge weight to each neighbor, with explicit presence bits so `u32::MAX` remains valid. It then rewrites only core-node CSR edges across eligible chains, using disjoint mutable CSR slices and the immutable table; there are no new unsafe pointers. All query endpoints are pinned; nonnegative self-return walks cannot improve an answer. If a direction is absent, a sum exceeds `u32::MAX`, or the chain exceeds 16 steps, the original entry is retained. Intermediate rows remain unchanged. All analysis and graph transformation take place at runtime.

Debug/overflow-checked candidate passed 16,000 independent random graph queries, all 36,864 three-node queries, 376 directed chain/cycle fixtures, a maximum-size max-weight chain and 6,000 repeated/unreachable queries; all 44 full-seed hashes from the paired batches and warmups matched. All-pairs tests pin all vertices and therefore do not themselves exercise shortening; use `../track-d-chain-shortcut/chain_stress.py` and the independent single-query graph tests when reviewing the transform. Independent source review found no concrete defect; `independent-shortcuts.py` also passed 1,200 mostly-unpinned random directed graphs at 1/2/7 workers, with 1,458 actual rewrites, plus targeted duplicate/weight/fallback fixtures. `boundary_property.py` verifies actual transformed CSR at the 16-step cutoff, missing arcs, pinned endpoints, zero cycles and 32-bit overflow. The independent review also examined bidirectional termination with unequal endpoint parallel edges: a simple shortest path split at core/query vertices has a common minimum-weight representation in both transformed directions; nonminimal transformed edges still denote real input paths. Additional exact-source tests covered 16,384 mostly-unpinned four-node directed chain/multiedge graphs and 1,024 reachable chains at 1/2/7 workers. See `independent-shortcuts.py`; this is review evidence, not a proof for all inputs.

In nine randomized full-data shared native ARM pairs (`report.json`), median wall was 0.25962 s vs baseline 0.27086 s, CPU 1.71754 vs 1.84100 s, peak process RSS 554,975,232 vs 535,543,808 B. A separate eleven-pair repeat (`repeat.json`) was 0.26399 vs 0.27208 s, CPU 1.74096 vs 1.85138 s, RSS 555,073,536 vs 534,364,160 B. These include preprocessing, show modest native wall gains with higher native memory, and do not establish Linux x86, official scoring or cgroup behavior. Candidate remains unselected. No Mac Docker was used.

## Dot VM x86 comparison

The parent-run shared native x86 VM observed wall 0.7–1.0% faster with 2–6.1% lower CPU and mixed native RSS. Across this, C AVX2 and A prefix packages, 300 full hashes, 24 alternate references and actual SIMD, guard, collision and graph transformation oracle checks passed. These are not official scoring-box or cgroup results. This remains isolated pending a larger or reproducible target advantage.
