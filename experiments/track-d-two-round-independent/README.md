# Independent two-round graph transformation check

`review.py` checks the production `contract` function from `../track-d-two-round/meeting.rs`, verifying candidate SHA-256 `6673a36206ac04e4154337a5ef90b774d3b35eb3b375d7bbe8430244d55eb709`. It compiles with debug assertions and overflow checks, dumps the intermediate graph after each round, and checks pinned-query distances against independent Floyd–Warshall, exact forward/reverse edge multisets, u32 weight bounds and the per-round conservative edge cap. It passed 120 randomized small directed graphs and 240 transformed CSRs. Inputs include sparse, dense, disconnected and loopy graphs, parallel and duplicate arcs, and zero and u32-maximum weights. This is a transformation test, not a speed, peak-memory, full-scale, x86 or official-scoring measurement.

The candidate's `baseline.rs` is the older u64-adjacency selected source, SHA-256 `ac9674a11b90244c63a518ee94eb7a9547353540ff564672aaa128ac4851a2ea`. The current official trial uses a different packed-adjacency CSR; the transformation cannot be transplanted without a deliberate rebase and renewed validation. Static review found no distance-equivalence or conservative-edge-bound defect. An independent set excludes adjacent removed nodes in either direction, query endpoints are pinned, shortcut weights fit u32, and retaining the prior graph on excess edge count preserves correctness. The edge cap does not constitute a complete 8 GiB bound: in particular worker-local search arrays, retained priority-queue capacities, and overlapping graph construction allocations must also be accounted for. Tests cannot prove memory usage for every valid graph.

There is no measured two-round speed gain. A previous one-round shared ARM full-data screen was slower than its baseline. Run a serialized representative sample screen first and proceed to full native and official comparisons only if it shows a meaningful improvement; assess memory and rebase correctness separately.
