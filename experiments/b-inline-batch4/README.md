# Track B inline four-token pipeline (not selected)

The candidate delays at most four completed token spans in a fixed stack array within the existing document scanner. It computes the four short keys/hashes, reads their initial table slots, then resolves exact comparisons in original token order; collisions use the unchanged exact lookup. Longer terms and terms over 32 bytes retain the original paths. The batch flushes before each document callback, so phrases cannot cross document boundaries. This differs from the earlier full-document vector/prefetch design; no prefetch is used. Bitmap limits, phrase summaries and Boolean semantics are unchanged. Baseline SHA-256 `322cc95ee08cf6d4abc5e1b52240753f66c7eaf89ab669cb6d72b0a8487dc458`, candidate `1f16c08616194a05fabf62418a4722dcff1f14072a7324237f06b353e7cfe43c`.

Eleven randomized warmed native shared-Mac ARM pairs gave candidate/baseline median wall 0.460836/0.434698 s and CPU 1.669286/1.634121 s; a 15-pair repeat gave 0.305621/0.291870 s and CPU 1.614907/1.602774 s. All 56 full hashes including warmups matched. Native scalar-fallback, contention, OS and CPU differences mean this is not x86 or official evidence; no stable local win was found and the candidate is not selected. `report.json` and `repeat.json` preserve samples.

The candidate passed 40 mixed-reference corpora, distributed top-ten/duplicate phrase and overlap, six >1 MiB lines, 250k-document/19k-duplicate-phrase stress and 3,072 alignment documents. A test-only all-short-hashes-zero version built with overflow checks passed another 40 mixed-reference corpora, exercising collisions and original fallback. Independent source review, real Linux AVX2/guard-page testing and target timing were not performed because the local screen lost. No Mac Docker was used.
