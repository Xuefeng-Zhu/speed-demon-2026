# C group-owned speed experiments

These prototypes are based on the prior 256-shard and current 1024-shard implementations, respectively; the 1024-shard source used for the paired baseline differs from commit b9c2b54 only in a comment. They remain experimental; timings are shared-host ARM native runs, not official x86 performance or cgroup memory. Both use exact-byte equality and have matched the full seed-1 hash, but need independent review before promotion.

`localset.rs` first deduplicates `(name, group)` in each parser worker, then merges these sets through the shared dictionary. Six measured pairs after warmup gave median 0.427 s versus 0.275 s for the older 256-shard selected baseline, with maximum process RSS 431 versus 226 MB; all 14 full outputs matched. It was slower and is not selected. Raw samples are in `localset-report.json`.

`groupowned.rs` bins each parsed `(name, group)` to a group owner, then deduplicates without shared dictionary locks. The cleaned source passed 120 independent reference comparisons; a pre-clean build with hash forced equal also passed 120. Six measured pairs before cleanup gave median wall 0.522 s vs 0.915 s for 1024 shards, median CPU 0.934 vs 1.193 s. A follow-up with cleaned code (while correctness tests were running) gave median wall 0.320 vs 0.298 s and median CPU 0.964 vs 1.122 s; maximum process RSS 395 vs 226 MB. Every full hash matched, but wall ordering reversed under contention. The raw follow-up samples are in `groupowned-report.json`. A portable x86 comparison package exists in Library, ID `libfile_4432ed7784a88191a1bbd36f2b5c1ae4`, SHA-256 `0637265e3f40445680b80d4ce378e6acb5641f9114e6c0192d06ab63205fc565`. No source was promoted.
