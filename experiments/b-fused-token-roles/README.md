# B fused token roles and anchor shortlist (unproven)

This experiment extends the earlier `b-fused-bool-scan` idea: Boolean posting-stream updates happen during tokenization, and a per-document vector records only phrase-anchor positions. Phrase checks visit that shortlist after the complete token sequence is available. The shortlist is cleared after each document and grows at most with that document's token count; existing per-chunk bounded phrase summaries and bitmap limits are unchanged. The full token sequence still preserves exact phrase matching, including overlaps. `baseline.rs` is selected B source SHA-256 `322cc95ee08cf6d4abc5e1b52240753f66c7eaf89ab669cb6d72b0a8487dc458`, and `candidate.rs` SHA-256 is `5da7abc489ed1cc380bfe144bc824a166d6ec0ab66c800d2aa811209297bc133`.

In two randomized, interleaved, warmed native shared-Mac ARM screens, all full seed-1 hashes matched. Seven-pair median wall was 0.3232 s candidate versus 0.2592 s baseline; a nine-pair repeat was 0.3077 versus 0.3650 s. Median CPU was 1.5712 versus 1.5850 s and 1.5814 versus 1.5935 s, respectively. Wall varied widely under shared-host contention, and the modest CPU difference is not enough evidence for a speed improvement. These are native scalar-tokenizer measurements, not x86 AVX2 or official cgroup scores; the experiment is not selected. Raw measurements are in `mac-arm-report.json` and `mac-arm-repeat.json`.

The candidate also passed 40 official-reference differential corpora using `B_RUST_BINARY=/tmp/b-ftr-candidate python3 experiments/b-bounded-fuzz.py experiments/b-rust-positional-adapter.py`, covering mixed ASCII/Unicode separators, case, repeated and overlapping phrases, operators, missing terms, duplicates and 32-byte terms. This is not a complete adversarial correctness review, nor evidence of x86 performance. Both sources were built with `rustc --edition=2021 -C opt-level=3 -C lto=fat -C codegen-units=1 -C panic=abort`; run `experiments/b-rust-lengthhash/compare.py` on independently generated data to reproduce. No Docker was used.

A separate instrumented baseline run on the full seed reported roughly 4.53 million tokens and 173–176 thousand anchor occurrences per chunk, with scan 465–505 ms, CSR construction 14–22 ms, and query evaluation 49–60 ms. Instrumentation and shared-host load alter timings, so these figures are diagnostic only.
