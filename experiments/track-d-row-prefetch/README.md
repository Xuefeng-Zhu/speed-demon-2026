# Whole-row distance prefetch (experimental, not selected)

The candidate reads an adjacency row once to prefetch each target distance slot, then makes the original exact relaxation pass. The AArch64 path emits `prfm pldl1keep`; x86-64 uses `_mm_prefetch` with T0; other targets use a no-op. Addresses are formed with `wrapping_add` from the live search allocation, and valid input node IDs index the array. Baseline is exact restored D source `451429c` (SHA-256 `1022f4d9c9956b17fd054e96a26d09551eff61936a851edf88505e12e2b1946c`). The x86 path has not been executed or independently reviewed.

All full seed-1 hashes matched; the ARM path passed 16,000 randomized queries, 36,864 exhaustive small-graph queries, a maximum-size maximum-weight chain and 6,000 repeated/unreachable queries. Nine shared ARM native pairs (`report.json`) had median wall 0.27142 s vs 0.28966 s baseline, CPU 1.90209 vs 1.84139 s; a separate 11-pair repeat (`repeat.json`) gave 0.27339 vs 0.27826 s wall, CPU 1.91078 vs 1.84905 s, peak native RSS 535,576,576 vs 535,789,568 B. Host variation and higher CPU make the small wall differences inconclusive. This is not an official x86/cgroup score; candidate is unselected. No Mac Docker was used.
