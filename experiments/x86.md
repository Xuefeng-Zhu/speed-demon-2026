# x86-64 sample correctness checks

Four isolated `linux/amd64` proxy images were built from snapshots of `submission/track-{a,b,c,d}` and run on OrbStack under x86 emulation. For each track, the official generator produced seed 1 at `sample` scale. All eight generated input files matched the seed-1 sample hashes in the official specs. Each container exited 0 and wrote exactly one output; all output hashes matched the published expected hashes:

| Track | File | SHA-256 |
|---|---|---|
| A | `summary.txt` | `ca6311bbeb536fa55d85265bf6fd3d24cc9586f13de1ac73bd2a23ac3893aac3` |
| B | `results.txt` | `eeeec1e9319da98a6f3c664c78f93e7078fd603c25c2bb3027174e81e3638a8f` |
| C | `aggregates.txt` | `9035fed36823232dd41ae2d1b9d6d21aa7c73f49d8e95647e953a89d5ebe9a66` |
| D | `distances.txt` | `a4c76ed030bc7e365db33191f6cf74708fba7f25eb48d64c8c4279f2e57046a0` |

The source hashes of the snapshots matched the submission source at completion: A `eac68d5812145a9449ba9d9c6f5277d998f5de99d1d3561b08510305d8f13341`, B `faab69540e03fa8f6eb1aee6277016f322044de80e9622dc646a564fd2a118d5`, C `7ed05471c64848511cf37b38a19bab1bfc520e078f4c9ca2da9b96fad1f2e174`, D `7a35d5a2fd2b84954e5dc3bc801078bd340ed0d5ae6fa6d80972ccd66eb6d3aa`.

The local daemon's image store already associated the allowlisted multi-platform index digests with ARM images. To avoid replacing existing images, **test copies only** substituted the exact amd64 child manifests, established by `docker buildx imagetools inspect --raw` on each official index:

| `rust:1-slim-trixie` | `sha256:d7d8fd94f01c80a355b86fe8691abc26be051daa44fa021a8b5ece5c8cbcb469` |

The original submission Dockerfiles retain the official allowlisted index digests. These proxy Dockerfiles are **not themselves valid submissions**. Each copy was built with `docker buildx build --platform linux/amd64 --network=none --load -t speeddemon-x86-check/track-<letter>:final /tmp/speeddemon-final-x86/track-<letter>`. `docker image inspect` confirmed `linux/amd64` for each image.

Each generated dataset was mounted read-only at `/data`, with an empty output directory at `/out`, using `docker run --rm --platform linux/amd64 --user 65534:65534 --memory 8g --memory-swap 8g --pids-limit 512 --network none --read-only --tmpfs /tmp:rw,size=1g,exec` plus the two bind mounts. This is a constrained smoke check, **not** the official harness: the official timer, cgroup memory peak, CPU pinning, filesystem diff and five-run procedure were not exercised. Emulated execution gives no meaningful competition timing. Data and proxy Dockerfiles are temporary under `/tmp/speeddemon-final-x86`.
