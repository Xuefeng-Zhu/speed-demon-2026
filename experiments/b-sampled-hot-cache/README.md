# B sampled hot-key cache (not selected)

This isolated candidate derives a direct-mapped 512-entry short-key cache from the existing input sample. Each slot retains the most frequent colliding sampled term; every hit verifies the exact key and misses use the existing table. It does not cache answers. Nine randomized warmed native shared-ARM full-data pairs all matched the published hash, but candidate median wall was 0.32685 s versus baseline 0.28731 s, and CPU 1.8249 versus 1.5951 s. Samples are in `report.json`. The slowdown is not evidence about AVX2 x86 but does not justify promotion here; deeper alternative-input and collision tests were not run. `profile.rs` and `profile.log` record one diagnostic instrumented baseline: query parse 17.1 ms, sample ready 21.2 ms, workers done 547.3 ms, total 554.3 ms, with instrumentation and shared-host interference. No Mac Docker was used.
