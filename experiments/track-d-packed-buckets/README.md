# Packed temporary edge buckets (experimental, not selected)

The candidate represents each parse bucket edge in 8 bytes: two 21-bit node IDs and a 22-bit weight code. A worker-local wide table holds weights of at least 2^21; the low 21 bits of a tagged code index it. A graph with more than 2^21 nodes or a parser worker exceeding 2^21 wide entries falls back to the original full parser. Both directions are built from compact buckets, and the search itself is unchanged. The graph and query data are read and processed at runtime. The candidate has not received independent review; the exceptional fallback paths have not been directly stressed.

The exact selected positioned-read baseline SHA-256 is `ac9674a11b90244c63a518ee94eb7a9547353540ff564672aaa128ac4851a2ea`; the candidate is `754cf3d369ea0493bc529aad1070074160febf29315f85d91bcfe9e624d68917`. Seven randomized native shared ARM full seed-1 pairs after one warmup produced the published hash in every run. Median wall time was 0.26848 s candidate versus 0.26912 s baseline, median CPU 1.77274 versus 1.76797 s, and maximum native process RSS 492,306,432 versus 534,773,760 bytes. The wall result is tied; the lower native RSS is not a cgroup measurement. See `report.json`. This is not target x86 or official evidence and does not justify a speed-first selection.

The overflow-checked candidate also passed 80 random directed graphs / 16,000 independent shortest-path queries, 4,096 exhaustive three-node directed graphs / 36,864 all-pairs queries, maximum-size maximum-weight chain and 6,000 repeated/unreachable queries. Tests do not prove all legal graphs or the unstressed fallback. No Mac Docker was used.
