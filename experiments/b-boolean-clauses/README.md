# B Boolean clause evaluation (not selected)

The prototype is based on the e6e72ac nine-worker C++ source (SHA-256 `3667c8f167a95137ff535ddcded3ae8e383b2a655f8d58373e4f1b6ab70d9967`). It distributes left-associative expressions into at most six union clauses: each AND or binary NOT applies to existing clauses, and OR introduces a new positive singleton. Each clause scans its shortest positive posting and tests other positive/negative memberships. Matching clause streams merge in ID order into count, sum and first ten IDs, deduplicating overlapping clauses. A conservative cost heuristic falls back to the existing sorted-vector set operations, including for pure OR. Existing bounded phrase summaries are unchanged.

This experimental source has not been selected or independently reviewed. Five paired native full seed-1 runs on the shared macOS ARM host matched the published hash: median wall 1.517082 s candidate versus 1.426269 s baseline, with substantial run variation; `mac-arm-report.json` contains the full measurements. The candidate was slower in this local screen, so no target-machine win is claimed.

A `-DCLAUSE_FORCE -fsanitize=address,undefined` build matched an independent oracle for 5,364 expressions across all 64 six-term membership patterns (including 5,000 randomized repeated-term expressions), 40 randomized official-reference corpora, distributed top-ten/duplicate phrase fixtures and >1 MiB read-boundary cases. This forced path tests clause semantics even when the production heuristic would select fallback.

Example: compile with `c++ -O1 -g -std=c++17 -pthread -fsanitize=address,undefined -DCLAUSE_FORCE experiments/b-boolean-clauses/candidate.cpp -o /tmp/b-clause-asan`, then run `python3 experiments/b-boolean-clauses/algebra.py /tmp/b-clause-asan` and `python3 experiments/b-bounded-fuzz.py /tmp/b-clause-asan`. The tested candidate source SHA-256 is `a53d81b514ea9f3eefecbd6c5f495c21694a46a383b32c356befbd4cc04aac99`. No Mac Docker was used.
