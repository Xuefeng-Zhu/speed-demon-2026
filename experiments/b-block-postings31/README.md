# B capped per-term block postings — unselected

`baseline.rs` is exact selected B source SHA-256 `7d371fe84ce9f0fd9d3c7e6fdf02b6b37e0f1440319c654161b990cf27bb8bf3`; the isolated candidate is SHA-256 `4d0cfb9917cedc10f010fad7ed7498e8f915621af2a11b348b5c6d8ff98fd023`. Per worker, it emits each deduplicated Boolean document ID directly into 32-ID per-term arena blocks, then traverses those lists in increasing term order to flatten the same sorted CSR consumed by the unchanged answer phase. Per-document `last` stamps, phrase matching and bounded summaries are copied from the original. The intermediate arena requests at most 32 MiB of block payload per worker, not a whole-process or cgroup bound. If exhausted, the attempt is abandoned and the untouched original indexer is rerun, after temporary data are dropped. That fallback and its worst-case memory retention were not independently tested or reviewed; this is not a correctness or hidden-data safety claim.

Seven alternating full-seed paired runs after one warmup each on a shared Mac ARM gave baseline/candidate median wall `0.231273/0.264946 s` and CPU `1.520354/1.725727 s`; all 16 outputs matched the official full-seed hash. A separate instrumentation-only full run reported 116,057–116,332 blocks per each of eight workers versus the 254,200 block cap, with no exhaustion, and the expected output hash. Thus the negative result was not explained by fallback for this run. Instrumentation is not timing evidence. The candidate is approximately 14.6% slower wall and 13.5% higher CPU in this screen, remains unselected, and has not received alternate-reference, forced-exhaustion, x86/AVX2, PGO, official or cgroup validation. ARM is not target timing; `arm-screen.json` has per-run results. No Docker was run on the Mac.

Reproduce the preliminary screen only with identical optimized builds, a separately generated official full dataset, and `python3 experiments/b-rust-lengthhash/compare.py --baseline <base> --candidate <candidate> --data <dir> --runs 7 --report <path>`. Further work would require an independent safety review, cap-zero/fallback tests, large-vocabulary and phrase oracle comparisons, and x86 protected-page testing before target use.
