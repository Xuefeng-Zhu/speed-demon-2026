# Track D compact radix entries with wide fallback (not selected)

The candidate packs a node id and distance into one 64-bit short-heap entry when the distance is below 2^43, and retains the original 64-bit-distance radix heap for larger distances. Every wide key is greater than every short key. This relies on the official full-size node bound of 1,740,512 (< 2^21); it is not an implementation for graphs with node ids >= 2^21. Distances and answers remain unrestricted in the wide heap. The selected baseline SHA-256 is `1022f4d9c9956b17fd054e96a26d09551eff61936a851edf88505e12e2b1946c`, candidate SHA-256 `61f93039c9519076b797debf60390d8dfd1072312ee14bfd988e91eb01004076`. An independent review found no defect under that bound; it is not selected.

Both builds produced the published full seed-1 hash in all 40 executions, including warmups. On a shared ARM Mac, seven randomized pairs first gave median wall 0.315012 s candidate versus 0.369348 s baseline, but the 11-pair repeat reversed to 0.338875 versus 0.306861 s. Repeat CPU medians were 2.061842 versus 1.846346 s; peak process RSS was 533102592 versus 536395776 bytes. Host contention was visible, and these are not x86, official wall or cgroup scores. The repeat and CPU results do not support promotion. Full results are in `report.json` and `repeat.json`.

Each heap pops short keys before wide keys because the encoded key ranges are disjoint. Once a wide key is popped, monotone Dijkstra relaxations cannot enqueue a short key, so independent radix `last` values remain valid. Node bounds are an explicit assumption, not verified dynamically in release builds. The candidate also passed 80 random directed graphs (16000 independent Dijkstra queries), all 4096 three-node directed graphs (36864 independent Floyd–Warshall queries), the maximum-size maximum-weight chain (which crosses the 2^43 cutoff), 6000 repeated/unreachable queries, and 21 independent Dijkstra cutoff cases including exactly 2^43−1, 2^43 and 2^43+1 with parallel and stale edges (`cutoff.py`). An independent heap model (`heap_stress.py`) also passed 450,000 monotone operations across 150 reuses with ties, duplicate keys, boundary node IDs and both queues populated, compared with a `BTreeMap` in an overflow-checked build. These tests do not prove correctness for every allowed graph.

Generate the full data independently, then run `python3 experiments/track-d-compact-radix/compare.py --data /path/to/full-d --build-dir /tmp/d-compact --report /tmp/d-compact.json --runs 11`; use `experiments/track-d-balanced-frontier/{oracle,exhaustive,extremes}.py` against `/tmp/d-compact/meeting` and `python3 experiments/track-d-compact-radix/cutoff.py /tmp/d-compact/meeting` for the stated correctness checks. No Docker was used.
