# Track C: Join

The task, the input files and the exact output format are in the [spec](https://github.com/hackathon-raptors/speed-demon-2026/blob/main/specs/c-join.md).

## Approach

One std-only Rust file, `src/main.rs`, with no crates. Where it relies on the generator guarantees of spec §2.2, which the spec allows for every seed including the holdout, the step says so.

1. **Read records through a small buffer.** Each worker reads its chunks of `records.csv` with `pread` into a 64 KiB buffer; when the parse reaches the end of the buffer, the unfinished record and the 32 bytes before it move to the front and the rest is refilled (the buffer doubles if one record fills it). Nothing of `records.csv` is mapped. `regions.csv` (2 MB) is mapped read-only, with an anonymous page after it so that 64-byte reads past its end are safe.
2. **Chunks.** The records after the header are cut into 16 chunks per thread, which the workers claim from an atomic counter. Each interior cut moves forward to the byte after the next CRLF. CR appears only as the first byte of a CRLF terminator (§2.2), so every chunk starts outside quotes. Chunk sizes shrink quadratically towards the end of the file, so the threads finish within about 0.2 ms of each other; cuts that collapse give empty chunks, which are skipped.
3. **Record ends by quote parity.** For each 64-byte block, AVX2 compares give masks of quotes and LFs. The prefix XOR of the quote mask (a carry-less multiply), carried from block to block, marks the bytes inside quotes, and a record ends at each LF outside them. The same masks count the quotes in each record.
4. **Fields from two windows.** A 64-byte window from the record's start gives the ends of the id and the name (the first two commas outside quotes) and the quotes in the name; a longer name continues 64 bytes at a time. Region ids have at most 7 digits and amounts at most 8 bytes (§2.2), so the 16 bytes that end with the amount hold its comma and either the region's comma or all of the region. One `pshufb`, from a 72-entry table indexed by the two lengths, right-aligns the region's digits and the amount's digits without the `.`; the 16 bytes that end with the id (at most 8 digits) fill the other 128-bit lane, and three multiply-add steps give all three numbers at once. `-5.25` becomes -525 integer cents with no floating point. A record start may carry a byte order mark, which is skipped.
5. **Never unescape.** The byte length of a value is its raw length minus its delimiting quotes and the number of `""` pairs. For counting distinct names, the raw bytes between the quotes serve as the key, because escaping is one-to-one, and an unquoted name (which cannot contain a quote) is byte-identical to its quoted form. `""` and an empty unquoted field both give the empty key.
6. **Distinct names by hash, counted by name owners.** Names are identified by 56 bits of a 64-bit hash, not compared byte for byte: two of about 10^5 names share them with probability about 7e-8 per dataset. Each 32 bytes of the name, zero padded, go through an AES round (the two halves as data and round key), two more rounds follow, and the 128-bit state is folded in half. On 10^7 synthetic names its top 36 and 40 bits collide as often as a random function's; with one round fewer they collided three times too often. Names are split between the workers by hash: a producer sends the event `hash & !0xFF | group` to the name's owner in blocks of 1,024 through the owner's inbox. The owner alone keeps its table of 8-slot buckets: eight keys, compared with two AVX2 compares, then for each of the four words of the 256-bit set of groups a name occurs in, that word of all eight names. One event so reads the bucket's key line and one line of group bits, and both are prefetched eight events ahead. The owner sets the group's bit and counts the name for that group the first time. If an owner's table passes 7/8 full, the run restarts with tables twice as large.
7. **Groups.** Every worker maps its share of `regions.csv` into a byte table indexed by `region_id`. Lines are found with LF masks; the comma is always 4 bytes before the LF. Countries are numbered from 1 in the order the threads first meet them, under a lock taken about 240 times; group 0 is `_UNMATCHED`, which also covers holes and ids past the end of the table. Records are parsed into batches of 64 and finished (group looked up, totals added, name event sent) when a batch fills, so the region entries prefetched meanwhile have arrived.
8. **Start and end.** The tables are anonymous maps without huge pages, so each thread faults in only its own pages and no two threads fault the same huge page. The workers wait until all have started before touching memory, because their page faults slow the creation of the next threads. Each worker keeps `[count, id_sum, amount_sum, amount_min, amount_max, names_distinct, name_bytes, note_bytes]` per group and merges it into one total. The main thread is worker 0: once all have merged, it writes the lines (countries by code, then `_UNMATCHED`) and ends the process while the other workers wait, so no thread is torn down.

## Correctness

- Byte-identical to the official reference on seed 1 `full` (`d8088b1cd42ba1338b1345b107b55db7b96ef1f5066f3ff64fd26a8912a0f536`), a locally generated seed 3 `full`, seeds 5 and 42 `sample` and seeds 2, 3, 7 and 99 `tiny`, on the seed 1 `full` file with its notes padded to 128-byte and to random-length records, and on fixtures with long names, records of 15–100 KB and a last record without a terminator.
- Under 1, 3, 5 and 8 CPUs, and in builds that force 2, 6, 12 and 16 workers. A build with a 128-byte starting buffer (so records cross refills and the buffer doubles) and a build whose tables start at 2^6 slots (so every run restarts several times) also pass.
- It builds without warnings with Rust 1.83 to 1.92.
- The chunk cuts and the field-length bounds rely on §2.2, as stated above. This is not a general parser for the broader §2.1 grammar alone.

## Dependencies

None (`dependency_count = 0`). `.cargo/config.toml` sets `target-cpu=x86-64-v3` (AVX2, BMI2) and the `pclmulqdq` and `aes` features, which x86-64-v3 does not include and the i5-13500 has, only when building for x86-64.
